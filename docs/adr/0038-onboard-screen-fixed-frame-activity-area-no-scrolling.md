# 车载屏：顶栏和右边一列固定，左边是随场景换的活动区；整屏不滚动，按了不能撤回的才确认

车载屏上显示什么全部由服务端决定（ADR 0024），但屏上该有哪些块、每个场景放什么、按钮放在哪，前几场没有定。第七场的经验是文字描述的页面产品负责人判断不了（2026-10-17），所以本场先做了可点的原型，产品负责人看了三十多个版本，逐条提意见改成下面的样子（2026-10-17、10-18）。车载屏是车上的横屏触摸屏，不支持手势滚动；用它的是车旁的人，不登录、不限人。本篇只定结构和规则，配色、字体、具体排版留给实现车载屏的票。

## 决定

### 整体框架

- 屏分三块（产品负责人 2026-10-18）：
  - **顶栏**：一直显示，见下文。
  - **右边一列**：每个场景都固定不变，上面是仓位，下面是行程。
  - **左边活动区**：随车当前的状态换内容，只放这个场景在乎的东西。例如车在路上时不显示本站任务、扫码和倒计时，到了站才显示（产品负责人 2026-10-18）。
- 断开、待确认的车载电脑、版本不符这三种情况，整块屏只显示一句提示，照 ADR 0024、0025、0026。
- **整块屏任何地方都不滚动，也不出现滚动条**（产品负责人 2026-10-18）：这块屏不支持手势滚动，滚动条在触控屏上也难按。放不下的清单（行程、任务清单）一律分页，用"上一页 / 下一页"大按钮翻。
- **按钮放在它所管的那一块上**，没有底部按钮条（产品负责人 2026-10-18）：例如"取消任务"在任务清单上，"立即出发"在倒计时旁边，"装货纠错""报告仓有问题"在仓位上，"解除二类急停"在急停的红色大块里。
- 按触控屏来做：按钮和格子都要大，要选的东西点整块，不用小勾选框（产品负责人 2026-10-17）。

### 顶栏

从左到右（产品负责人 2026-10-18）：

- **车辆标识**。
- **"负责 N 类任务 ▸"**：只写几类，点开列出这台车所属的派车区（中文名加编号，例如"焊线区 WIRE_BONDING"）和它负责的每个任务类型、从哪送到哪（ADR 0023）。为此**每个派车区在参数配置里多一个中文名**（产品负责人 2026-10-18）。
- **屏上的任务类型一律写中文名**，不写英文编号，没人看得懂（产品负责人 2026-10-18）。为此**每个任务类型在参数配置里也多一个中文名**，D8 的起始配置（产品负责人 2026-10-18 确认）：STAGING_TO_WIRE 待送区送焊线、WIRE_TO_GATE 焊线送关卡、WIRE_TO_OPTICAL 焊线送三光、DIE_TO_WIRE_STAGING 装片送待送区、DIE_TO_OVEN 装片送烘箱；管理员以后可以改。
- **位置**：车停在站点上时写站号和站名（站名取地图上的名字）；在两站之间写"不在站点上，刚经过"某站。一直显示（产品负责人 2026-10-18）。
- **"车体状态 ▸"**：全部正常写"车体状态正常"；有不正常的就写出是哪几项；只是避障、等交管这类提示时用提醒的颜色。点开看全部 11 项（见下文"车体状态"）（产品负责人 2026-10-18）。
- 电量、和服务端连没连着。

### 右边一列：仓位和行程

- **仓位**：按车辆清单里的仓位分组摆，D8 的车是车前 1～4 号、车后 5～8 号，各自自上而下，两列标题就写"车前""车后"（产品负责人 2026-10-17、10-18）。装了货的格子只写子批；点一下弹出这个仓的详情：仓位、子批、封装形式、任务类型、取货地点、装进时间（关门的时刻）、目的地。取货地点和目的地是固定站点就写站名（不加"固定站点"字样），是机台就写机台号和区域号（产品负责人 2026-10-18）。停用的仓、门开着的仓、有问题的仓各有标记。
- **机台一律写成"机台号 · 区域号"**，机台号在前，例如"W-0312 · N1-3"；屏上凡是出现机台的地方（任务清单、行程、仓位详情、位置、确认框）都这样写（产品负责人 2026-10-18）。
- 右边两块的标题叫"仓位信息"和"行程"；左边取货站、卸货站上的清单叫"本站任务"（产品负责人 2026-10-18）。
- **行程**：按顺序列出车接下来去的每一站，每站带序号，只排一列；最后一站是这一趟结束后的预计去向（回等待点，或电量低时去充电）。**一个子批装完（装满应装花篮数，或人选了"就装这些"）才把它的卸货站加进行程**：还没有装完的子批时只显示取货站，下面一行写"一批装完后才显示卸货站"（产品负责人 2026-10-18：没装货就不知道送到哪里，装到一半也不更新）。每个卸货站大字写机台号和区域号（固定站点写站名），小字逐条写哪个子批卸几仓，例如"B89-1012-H-1 卸 2 仓"（产品负责人 2026-10-18）。一个区域号只对应一台机台、一个站点（ADR 0002），所以一站不会有几台机台。后面还要去的取货站也列在行程里，写"取货几条"，排在卸货站前面（ADR 0004）。所以两种方向的行程表现不同：从固定站点送机台（例如派工待送区），装完一批多一站卸货站，离站后就不再变；从机台送固定站点，车沿途在几台机台取货，停站时冒出的新需求会追加成后面的一个取货站（ADR 0004），行程一路在变（产品负责人 2026-10-18）。每个场景都显示：空闲时是"停在等待点"，充电时是"充电桩 → 充满后回等待点"，停用时写"没有行程"（产品负责人 2026-10-18）。一页放不下就分页，"上一页 / 下一页"一直在行程标题旁边，只有一页时变灰（产品负责人 2026-10-18）。行程是服务端此刻的计划，追加、取消任务后跟着变；和控制台车辆详情里的"接下来去哪几站"是同一份（ADR 0029）。

### 左边活动区，按场景分

| 场景 | 放什么 |
| --- | --- |
| 在取货站 | 指示卡片：一句大字指示（扫码、放哪个仓）；等扫码时下面是扫码框和"确认"按钮；离站倒计时也在这张卡片里，全部装完时旁边是"立即出发"（ADR 0035）。下面是本站任务，标题栏上有"取消任务" |
| 在卸货站 | 大字指示（取哪个仓）；本站任务（这一站要卸的）。卸货站没有倒计时（ADR 0005） |
| 在路上（去取货、去卸货、空闲返回） | 大字"正在去"哪一站，到站后做什么 |
| 空闲 | 停在哪个等待点、能不能接任务 |
| 充电 | 电量，以及去充电线、可接活线、充满线（ADR 0020） |
| 出问题（急停、故障，包括服务端自动认出的仓位故障） | 红色大块：发生了什么、车旁的人该做什么、能按的按钮（只有二类急停有"解除二类急停"）；下面是车上的货。处置照旧都在控制台（ADR 0012） |
| 停用 | 写明车已停用；右边每个仓位格上有"开门"，可以同时开几扇；停用的仓也能直接开，不用先重新启用（ADR 0011、0012，产品负责人 2026-10-18） |

- **任务清单**每行写：子批；从哪 → 到哪（机台写机台号 · 区域号，固定站点写站名，例如"W-0312 · N1-3 → 关卡""派工待送区 → W-0312 · N1-3"）；已放/应放的篮数（例如 1/2）；放在哪几号仓（例如"仓 1、2"）；状态。任务类型不单独写，看目的地就知道是哪一类。翻页按钮常驻，只有一页时变灰（产品负责人 2026-10-18）。
- 扫码框带"确认"按钮，给键盘输入用；扫码枪扫完自带回车，不用按（产品负责人 2026-10-18）。
- 离站倒计时放进指示卡片，和扫码框在一起：它的意思是"多久之内扫码，不然车就走了"（产品负责人 2026-10-18）。
- 在路上时，避障、等交通管制、订单挂起用一条提醒横幅说明，挂起的原因按车队调度系统给的原因码写（ADR 0010）。
- 空仓关门的提问照 ADR 0005 和 0035："重新打开"或"取消这条任务"（第一个仓），"重新打开"或"就装这些"（之后的仓）。卸货时关门仓里还有货，照旧只给"重新打开"，要人点，不自动弹开（ADR 0005，产品负责人 2026-10-17 确认）。

### 哪些按钮要确认

- **按了不能撤回的，按一次确认**，确认框里一句话说清会发生什么（产品负责人 2026-10-17）：取消任务、就装这些、立即出发、解除二类急停、报告仓有问题。触控屏会误触，这几样按错了就收不回来。
- **按错了也没关系的不确认**：重新打开、装货纠错（点仓直接开门）、停用的车上开门。
- 要选的东西先在屏上点选，再确认：取消任务时先在任务清单上点选一条、几条或全选，再按"取消选中的 N 条"弹出确认；装货纠错和报告仓有问题，按了以后直接点仓位格（产品负责人 2026-10-17）。
- "这个仓有问题"按钮（ADR 0012）在屏上叫"报告仓有问题"，作用不变（产品负责人 2026-10-18）。

### 车体状态

- 共 11 项，全部是服务端本来就从车队调度系统读的车体事实：急停（没有，或哪一类）、抱闸、自动或手动模式、定位、车体故障、订单状态、在走还是停着、交通管制、充电、调度上下线、车队调度系统连没连上（产品负责人 2026-10-17）。
- **只显示，不加任何新规则**：例如抱闸松开本来就按手动用车算故障（ADR 0022），这里只是让车旁的人看得到（主持会话补，产品负责人 2026-10-18 确认）。
- 避障没有明确的读数：上一代行为实验室第 44 轮里，车在路上停了 36 秒，读数只有"车辆暂停"，订单照常执行，没有急停也没有故障码，"有人靠近在避障"是现场的人口头说的。所以屏上只写"停着，可能在避障"（产品负责人 2026-10-17）。等交通管制有明确读数（车在等通行点，实验室第 26 轮），直接写"在等交管"。

### 边界情况怎么显示

产品负责人要求把边界情况补齐（2026-10-18），原型逐个做了下面这些：

- **按下后**：被按的那个按钮自己变成"处理中…"，屏上其余按钮暂时变灰，不另弹浮动提示；服务端做完就换成新画面（ADR 0024，产品负责人 2026-10-18）。
- **服务端明确拒绝执行**（例如按"解除二类急停"时车上还有 SIMPLE 下的急停）：按钮恢复原来的字，下面一行红字写原因，和控制台"没做成用一句话说明原因"（ADR 0030）同一个做法。ADR 0024 "不另设'刚才的操作没有生效'的提示"管的是按键迟到、回答旧提问这类点了不算的情况，照旧靠网络不好时先让按钮变灰来避免；按的时候情况已经变了的，仍由新画面说明。
- **网络卡顿**：2 秒没收到新鲜的下发状态，按钮和扫码框先变灰、连接处写"网络不稳"；3 秒才整屏显示"与服务端断开"（ADR 0024）。
- **离站倒计时走完**：先显示"装货时间已到，车即将离开"，写明没开始装的按站点超时结束、装了一部分的照常送；按了"立即出发"的写"车即将离开这一站"。这时屏上若开着确认框，框自动关掉并说明没有执行。
- **控制台那边取消了本站的任务**：那一行变成"已取消"，提醒横幅写明是控制台取消的、这条不用装了。
- **不是故障的告警**（ADR 0013 规定显示在车载屏上，给车旁的人）：用提醒横幅写清是什么事、该做什么、多久没处理会通知班组长。例如门开着或卸货 10 分钟没有进展；电量低于紧急充电线又没在充电，写明原因（例如能去的充电桩都停用了）。
- **充电失败**（ADR 0020）：一到桩就充不进、充到一半不涨了，都用红色大块写明电量从多少到多少、多久没涨，车停在桩上等班组长；充到可接活线以上才不涨的，不算故障，用提醒横幅写"当作充满"，车回等待点。
- **充电时让位**（ADR 0020）：提醒横幅写明让给哪台车、为什么（例如"agv01 电量 18% 在等桩，这台车已过可接活线"），行程写回等待点、有活就直接去接活。
- **空闲但接不了任务**：空闲的大字块里写明原因，例如"电量低，等桩——1 号桩被 agv01 占着"，行程写"在等待点等桩 → 有空桩就去充电"（ADR 0011、0020）。
- **手动用车**：红色大块写明是哪种迹象，以及"要手动用车，请先在控制台停用这台车"（ADR 0022）。
- **同时有几个故障**：红色大块里逐条列出，每条写明怎么结束（ADR 0037）。

## 考虑过的做法

- **每个场景同一套格子，只换内容**（原型前几版）：车在路上也看得到"这一站的任务"、扫码和倒计时，人要自己分辨哪些现在有用。
- **三种布局任选**（指示在左、仓位在右；仓位按车身摆在两边；车体、指示、仓位三栏）：产品负责人选了第一种的方向，再改成现在的样子。
- **底部一条按钮栏放所有按钮**：按钮和它管的东西离得远，产品负责人要按钮落在对应的块上。
- **行程放不下就在框里滚动**，或者**折成两三列**：屏不支持手势滚动；折列读起来乱，产品负责人改成一列分页。
- **任务清单按任务类型分组、每组一行标题**：多占地方；产品负责人改成让人看目的地认任务类型。
- **车体状态单独占一行常驻在屏底**：11 项都摆出来太多，也没写每项是什么；挪到右上角，正常时只占一个按钮。
- **仓位格写全子批、送哪、状态**：格子挤，信息多了反而看不清；只写子批，详情点开看。
- **所有按钮都确认**，或**都不确认**：前者每次多按一下，后者触控屏误触收不回来。
- **"在做什么"常驻顶栏**：和左边活动区重复，换成了位置。

## 后果

- 下发状态要能描述这些块：仓位格和点开后的详情、行程、车体状态的 11 项、负责的任务类型、位置。它们仍是"屏上显示什么"，车载终端照着画，不做业务判断（ADR 0024）。分页、点开详情、在屏上点选是车载终端本地的显示动作，不是车旁操作；只有确认后的那一下才作为车旁操作发给服务端。
- 原型的最后一版留给实现车载屏的票参考（见 #53 的评论）；原型只用来对齐结构，长相不照搬。
- 参数配置多两项：每个派车区的中文名，每个任务类型的中文名。
