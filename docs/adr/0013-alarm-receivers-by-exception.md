# 告警接收人按"是不是故障"一句话定，不是故障的不升级到专业人员

告警给谁，不用一张逐条规定的升级表，而是按"是不是故障"推出来。上一代的规程是所有阻断都按"当站操作员 →（10 分钟）班组长 →（30 分钟）维护管理员"升级，可门开太久这类事找维修的人没有用。有了"异常"和"故障"两层（见 `CONTEXT.md`），以后新加一种异常，只要先判断它是不是故障，接收人自然就定了，不用再往表里加行，也挡住了需求越堆越多（产品负责人 2026-10-16）。

## 决定

接收人分三种：现场人员（当站的操作员）、班组长（现场的管理人员）、专业人员（处理故障的系统管理员或被授权的人）。三种接收人具体对应哪些岗位和账号，由人员与权限的决定定。（已定，见 ADR 0014：现场人员即车旁的人，看这台车的车载终端；班组长是本项目的班组长账号；专业人员并入班组长。）

- **不是故障的**，告警给现场人员，30 分钟没解决升级给班组长，不再往上升级。
- **是故障的**，告警给专业人员，不升级。服务端自动恢复不了、停下交人的情况都算故障（ADR 0012）。
- **服务端已经自己恢复的**（失败或被取消后已重建、被下线后已重新上线、故障已自动结束），不是告警，只在控制台提示，不需要谁处理。
- **唯一的例外**：急停发出后没确认、车可能还在动（ADR 0009），现场人员和专业人员同时给，不升级，因为要有人马上去车旁按急停按钮。

现场人员到了车旁发现其实是硬件坏了，按车载屏上的"这个仓有问题"，它就变成故障，转给专业人员（ADR 0012）。

**举例**（都由上面四句推出，不另作规定）：

| 告警 | 是不是故障 | 给谁 |
| --- | --- | --- |
| 车在取货站或卸货站上等人没动静（ADR 0012） | 不是 | 现场人员，30 分钟升级班组长 |
| 车被别人下了一类或二类急停（ADR 0009） | 不是 | 现场人员，30 分钟升级班组长 |
| 订单挂起，还没到"继续不了"，原因不是在 Matrix 上取消（ADR 0010） | 不是 | 现场人员，去车旁合抱闸、松急停按钮之类；10 分钟没继续成功就转成故障，所以实际到不了升级 |
| 挂起转成故障、在 Matrix 上取消引起的挂起、挂起过又被取消且条件不满足、单或车反复需要恢复、外来单取消不掉（ADR 0010、0011） | 是 | 专业人员 |
| 仓位故障、车载终端故障等各类故障 | 是 | 专业人员 |

- 升级时长放在厂区配置里。
- 告警显示在控制台上；跟某台车有关的，同时显示在这台车的车载终端屏上。
- 第一版不推送消息，不承诺有人值守。推送渠道（例如企业微信）另定。

## 考虑过的做法

- **沿用上一代的三级岗位升级**：所有告警走同一条线，门开太久最后会升级到维修的人手里，而他处理不了。
- **现场人员没解决就升级给专业人员**：同上，不是故障的事专业人员帮不上忙。
- **逐条列表规定每种告警给谁、多久升级**：每加一种异常就要往表里加一行，接收人还会因为各行写法不同而前后不一致。
