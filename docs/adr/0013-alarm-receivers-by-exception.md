# 告警按异常逐类定接收人，不是故障的不升级到专业人员

告警的接收人按异常的种类定，不用一张统一的升级表。上一代的规程是所有阻断都按"当站操作员 →（10 分钟）班组长 →（30 分钟）维护管理员"升级，可门开太久这类事找维修的人没有用。有了"异常"和"故障"两层（见 `CONTEXT.md`），不是故障的异常只在现场这条线上升级，故障直接给专业人员；现场发现其实是硬件坏了，按车载屏上的"这个仓有问题"把它变成故障（ADR 0012）。

## 决定

接收人分三种：现场人员（当站的操作员）、班组长（现场的管理人员）、专业人员（处理故障的系统管理员或被授权的人）。三种接收人具体对应哪些岗位和账号，由人员与权限的决定定。

| 告警 | 先给 | 多久没解决升级 | 升级给 |
| --- | --- | --- | --- |
| 仓门开着超过一段时间（ADR 0012，取货站、卸货站） | 现场人员 | 30 分钟 | 班组长 |
| 卸货站一段时间没有进展（ADR 0005） | 现场人员 | 30 分钟 | 班组长 |
| 车被别人下了一类或二类急停（ADR 0009） | 现场人员 | 30 分钟 | 班组长 |
| 订单挂起、自动继续不了（ADR 0010） | 专业人员 | 不升级 | |
| 移动单被反复取消、车被反复下线，达到上限后停下（ADR 0010、0011） | 专业人员 | 不升级 | |
| 外来单取消后仍没结束（ADR 0011） | 专业人员 | 不升级 | |
| 各类故障 | 专业人员 | 不升级 | |
| 服务端已自己恢复的（失败或被取消后已重建、被下线后已重新上线、故障已自动结束） | 只提示，不需要谁处理 | 不升级 | |

- 升级时长放在厂区配置里。
- 告警显示在控制台上；跟某台车有关的，同时显示在这台车的车载终端屏上。
- 第一版不推送消息，不承诺有人值守。推送渠道（例如企业微信）另定。

## 考虑过的做法

- **沿用上一代的三级岗位升级**：所有告警走同一条线，门开太久最后会升级到维修的人手里，而他处理不了。
- **现场人员没解决就升级给专业人员**：同上，不是故障的事专业人员帮不上忙。
