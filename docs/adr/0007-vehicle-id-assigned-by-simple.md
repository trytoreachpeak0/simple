# 车辆标识由 SIMPLE 分配，换了车载电脑要人确认

SIMPLE 用自己分配的车辆标识认车，不从车载电脑或车队调度系统推断。首个厂区三台车的车载电脑是同一个系统镜像克隆出来的，机器名和硬件 GUID 都一样；车载电脑还会因维修被更换；车队调度系统里的 `deviceKey` 和 `id`，同一辆车也可能变。这三样都不能代表"哪辆车"。

## 决定

- 车辆标识登记在厂区配置的车辆清单里，同时记下它当前对应车队调度系统里的哪台车。车队调度系统那边的编号变了，由人改车辆清单，车辆标识不变。
- 每台车的车载终端在本机、仓库外的配置里写着自己的车辆标识，车载终端上报时只用这个值。
- 服务端第一次见到某台车载电脑，或发现某个车辆标识换了一台车载电脑，先不接受它的上报和命令，在控制台提示，由人确认"这是哪台车"后才放行。怎么认出"换了电脑"由实现决定；因为克隆出来的电脑机器名和 GUID 相同，不能靠它们。

## 考虑过的做法

- **用车载电脑的机器名或 GUID 认车**：克隆镜像让三台车的这两个值完全一样，分不出来。
- **用车队调度系统的 `deviceKey` 认车**：是厂家系统里的值，同一辆车也会变，换车队调度系统时更会全部变掉。
- **只信车载终端配置的车辆标识，不做人工确认**：换了电脑或配置抄错时，一台车会冒充另一台车，服务端把别的车的任务和仓位状态套在它身上。
