# 区域号与站点的对应以地图为唯一来源

区域号对应哪个站点，只看车队调度系统地图上的站点：站点上写着它服务哪些区域号，SIMPLE 读地图得到对应关系，不另建对应表，也不允许在配置里人工覆盖。现场加一个区域号时只改地图一处；维护两处（地图上建站点、配置表里再加一行）既麻烦又容易配错，上一代系统就出现过配置和地图对不上而没人发现的情况。

## 决定

- 区域号是一串不透明的文字，比较前只去掉首尾空白，其余原样比较，不补零也不去零：`5` 和 `05` 是两个不同的区域号，`5` 和 `5 ` 是同一个。区域号由现场设备工程师设定，格式因车间而异，同一厂区里就有补零和不补零两种。
- 厂区配置里只放地图表达不了、而且都有默认值的设置：区域号归哪个派车区（默认归所在地图的默认派车区），以及明确列出的"不服务"区域号。所以加新区域号只改地图；要停送某个区域号，在配置里关掉即可，不必去地图上删站点或改站点名。（开门侧例外：无默认值，见 ADR 0006。）（已改，见 ADR 0015：取消"所在地图的默认派车区"，每个区域号都要在配置里写明归哪个派车区，和开门侧一样没配就不派、告警。）
- 对应关系只能通过改地图来改。控制台显示 SIMPLE 读到的对应关系，并报告对不上的情况，例如 MES 里有某区域号的需求而地图上没有站点。
- 一个区域号只对应一台机台、一个站点。有两种情况算作重复，都告警并停止往这个区域号派新任务：
  - 地图层：两个站点声明了同一个区域号，无论在不在同一张地图上、属于哪个项目（ADR 0015）；
  - MES 层：SIMPLE 服务的区域号（地图上有站点的）在 MES 里对应了不止一台机台。MES 系统本身不阻止录入重号，但一个区域号对应多台机台是 MES 的数据错误，由客户在 MES 里修正，SIMPLE 不做任何兼容。只看 MES 也分不清这些机台在不在同一个车间：即使另一台机台在 SIMPLE 不服务的车间，它产生的需求也会被派到这个站点。

  现场有人工送货兜底，而送错地方是严重错误，所以宁可停派。重复消失后（地图或 MES 改好），SIMPLE 自动恢复派车并在控制台留下记录。发现重复时已在执行的任务不自动取消，在控制台挂上告警，由人决定照常送到，还是在控制台放弃（车上还没有这条任务的货时，ADR 0003）。

上一代系统的资料里写过"一个区域号可以对应多台机台"，这是错的，SIMPLE 不沿用。

## 考虑过的做法

- **按站点名解析，配置里可以人工覆盖**：真相分在两处，出问题要查两个地方。
- **厂区配置里放一张明确的"区域号→站点"对应表**：真相在 SIMPLE 手里、便于校验，但每加一个区域号都要改地图和表两处，被否决。

## 后果

- 首个厂区 2026-07-24 的 MES 样本（672 行，501 台机台对应 493 个区域号）里，有 8 个区域号各对应 2 台机台。上线前要请客户在 MES 里修正，否则这些区域号会被停派。
- 区域号在地图上具体怎么写（站点名还是站点属性），取决于车队调度系统支持什么，由适配器的实现决定。
