# 一台车同时有几个故障就报几个；"继续"按车一次收掉，全部结束处置才结束

车载电脑关机或断电时（AGV 关机时车载终端立即断电，产品负责人的说法，未实测，#11），服务端会差不多同时看到两件事：车载终端断联超过 2 分钟，是车载终端故障（ADR 0009、0024），重连后读数一致就自动结束；车在车队调度系统里离线超过 2 分钟，是车辆本体故障（ADR 0008），一律经故障处置按"继续"结束。原来的规则没说一台车同时有两个没结束的故障怎么办：告警出几条，统计算几次，其中一个自动结束了处置算不算结束。主持会话提过"一台车同一时刻最多一个故障，后来的并进去当原因"，产品负责人否掉了：一个故障带几个原因，屏上不好显示；更要紧的是让人看懂车到底出了哪些问题，故障就该如实一条一条报（2026-10-17）。

## 决定

- **一台车同时有几个没结束的故障，就报几个**（产品负责人 2026-10-17）。每个故障各有自己的类别、告警和记录：告警栏里各占一条（ADR 0013、0029），统计里各算一次、各算各的用时（ADR 0019）。上面关机的例子就是两个故障、两条告警。
- 这样定的出发点是让人看懂车出了哪些问题，不按客户验收指标（例如 MTBF）的口径来定。关机、断电这种情况多报一个，对这类指标影响不大（产品负责人 2026-10-17）。
- **故障处置按车，不按故障。** 车上出现第一个故障时进入故障处置；之后再出现的故障，进同一个处置，控制台车辆详情最上面把这台车所有没结束的故障都列出来（ADR 0029）。处置的动作仍只有"继续"和"取出货物交人工"（ADR 0012）。
- **"继续"按车，一次收掉这台车上所有要人按"继续"才结束的故障**（产品负责人 2026-10-17）。按之前服务端照 ADR 0012、0022 核对条件，条件管的是整台车（门锁、手动用车迹象、旧单读回），所以一次核对就够；条件不满足就整个不执行，写明原因。车载终端还没连回来时，门锁读数不新鲜，"继续"本来就按不了（ADR 0009）。
- 能自动结束的故障（例如车载终端重连后读数一致）各自自动结束，告警随之消失。**车上还有别的没结束的故障，处置就不结束**；所有故障都结束了，处置才结束（产品负责人 2026-10-17）。最后一个故障是自动结束的，就照 ADR 0012 的规矩按这一趟剩下的任务重建：先等 30 秒、核对门锁、计入刹车（ADR 0008）。
- 停用这台车时，车上所有没结束的故障一起结束，结局都记"停用"（ADR 0011、0012）。
- 例外照旧：车上已经有没结束的故障时，人松抱闸把车推开，不另算手动用车（ADR 0022）。

## 考虑过的做法

- **一台车同一时刻最多一个故障，后来的问题并进去当作又一个原因**：告警只有一条、统计只算一次，但一个故障挂几个原因，屏上不好显示，人也看不出车到底出了哪几样问题（产品负责人 2026-10-17）。
- **只为关机这一种情况特别合并**（例如两个同时出现只算车辆本体故障）：以后再碰到别的两个故障碰在一起，每次都要再加一条规则。
- **每个故障各自要按一次"继续"**：同一台车、同一套核对，按几次没有意义，只会让人以为按了没生效。

## 后果

- 关机、断电一次，统计里是两次故障（车载终端故障、车辆本体故障）。客户验收指标的口径要和客户对过再定（ADR 0019），到时候可以按需要合并统计，不影响这里的记录和告警。
- 改写 ADR 0012"处置中的故障自己结束了，处置也随之结束"一句：只有车上已没有别的没结束的故障时才这样。
