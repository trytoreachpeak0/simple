# 固定站点读地图，区域号的开门侧放厂区配置

任务类型的固定站点（烘箱、关卡、派工待送区等不是机台的那一头）和 ADR 0002 一样只看地图；但区域号用车的哪个仓位分组（开门侧）放在厂区配置里，是 ADR 0002"区域号的事只看地图"的有意例外。开门侧写进地图只能写在站名或站点的自定义属性里，而车队调度系统没有批量修改这两样的入口，一次改很多个站点很麻烦；厂区配置是文本，可以一次改很多行。开门侧很少变，上一代按区域号放在配置里也一直可用。

## 决定

- 固定站点在地图上声明自己是哪个任务类型的固定站点，SIMPLE 读地图得到对应关系。每个任务类型在每张地图上最多一个固定站点；不同任务类型不共用一个站点。违反任一条都视为配错，在控制台告警，停派受影响的任务类型。
- 开门侧以区域号为键写在厂区配置的区域号设置里，与"归哪个派车区""是否停送"放在一起，没有默认值。区域号在配置里没写开门侧，就不往它派任务，并在控制台告警，不静默跳过。
- 开门侧不从站名、站点朝向推算：站点朝向是所在路线的方向，看不出车停下时哪一侧对着机台。
- 每台车有几个仓位、怎么分组，是车型的硬件事实，写在厂区配置的车辆清单里。

## 考虑过的做法

- **开门侧写进站名**（例如在区域号后加标记）：在车队调度系统界面上一眼可见，但站名变长，现场改站名时容易改坏，也没法批量改。
- **开门侧写进站点的自定义属性**：改站名不影响它，但同样没法批量改，建站时还容易漏填。
