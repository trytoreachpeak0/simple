# MES 网关送来没配置的任务类型：不派车，在控制台告警

任务类型由 SIMPLE 定义，不是 MES 里的字段：MES 网关读 MES 的查询是我们写的，查询里每一段的结果由我们写死叫哪个任务类型（网关每行带的 `TASK_TYPE` 列见 `src/Simple.MesGateway/Sources/MesRow.cs`；上一代是一条查询、六个分支）。但网关的查询和服务端参数配置里"有哪些任务类型"是分开配的，两边对不上时（网关加了一段、服务端没加，或名字写错一个字母），服务端会收到它不认识的任务类型的需求。#1 留下的"MES 里出现没配置的任务类型怎么办"指的就是这种情况；本场起初以为它不会发生，审查查了代码后指出会发生（2026-10-18）。

## 决定

- 服务端**不派**这些需求，在控制台**告警**，写明是哪个任务类型、有几条，例如"MES 网关送来了没配置的任务类型 WIRE_TO_GATTE，共 3 条，没有派车"，并记进事件记录（ADR 0019）（产品负责人 2026-10-18）。
- 管理员在参数配置里补上这个任务类型后，从下一次选需求起照常派（ADR 0017）。在这之前这些货由人工送。
- 它算一次配置故障：服务端自己恢复不了，要停下交人（ADR 0013），和 ADR 0023 里"需求落在负责它的车的派车区之外"同样处理。产品负责人确认的是"告警给专业人员"；ADR 0014 已把告警接收人改成按角色分，配置故障不属于任何项目，告警给所有项目的班组长，标明"等管理员处理"，本篇照这个写（主持会话按 ADR 0014 换算）。
- 配置补上，或这些需求从 MES 消失，告警就结束（主持会话补，产品负责人 2026-10-18 确认）。

## 考虑过的做法

- **悄悄忽略，不派也不告警**：配错了没人知道，这类货一直没车送。
- **把"不会发生"当前提，不处理**：两处配置分开，写错是迟早的事。

## 后果

- 规则总览原来写的"MES 里出现没配置的任务类型不会发生"改成本篇的做法。
