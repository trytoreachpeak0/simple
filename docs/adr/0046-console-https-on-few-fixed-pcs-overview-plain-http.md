# 要登录的控制台只在固定几台电脑上用，走服务端自己生成的证书加密；车辆一览页在所有电脑上走明文

ADR 0045 定了怎么登录。控制台一对厂区网开放，账号口令和登录凭条就在网上传：走明文的话，能在那段网络上抓包的人（有一段是 Wi-Fi，或交换机上开了镜像口）都看得到，其中工程师账号的口令就是这个项目的动车授权（ADR 0016）。ADR 0025 正是为了"能在厂区 Wi-Fi 上抓包的人"给车载终端加了双向加密。这一篇定控制台在厂区网上的入口和加密。

现场的条件（产品负责人 2026-10-17）：厂里有几千台电脑，有线和 Wi-Fi 都有，归不归客户 IT 统一管不知道；车间里的电脑不可能一台一台装证书。要登录的控制台**只在固定几台电脑上用**；不用登录的车辆一览页（ADR 0016）要在所有电脑上都能打开。

浏览器自己加密只有一种方式，HTTPS（TLS），而 HTTPS 一定要有证书；浏览器不支持不用证书的加密。所以要么证书来自浏览器本来就信任的地方（公共证书机构，或客户 IT 配好的内部证书体系），要么在用的电脑上装一次证书，要么把加密放到浏览器外面做（SSH 通道、IPsec），要么不加密。调研于 2026-10-17 读了微软、Let's Encrypt、CA/Browser Forum 的文档和 Chromium 的源码。这是纯技术题，先出方案、讲清现场后果，再由产品负责人挑。

## 决定

- **服务端在厂区网上有两个给人用的入口**，和车载终端的入口（ADR 0025）一样，各自只听一块指定网卡的地址，不听全部网卡，各自只回自己那一份（按请求进来的那条连接分，不按主机名或端口）：
  - **控制台入口，走 HTTPS**：控制台的页面、全部接口和登录（ADR 0045）都在这里。TLS 1.2（factory01 是 Windows Server 2016，没有 TLS 1.3，浏览器都支持 1.2）。
  - **车辆一览页入口，走明文 HTTP**（产品负责人 2026-10-17）：只回车辆一览页和它的数据，不收登录，别的什么都不回。车辆一览页不带口令，内容只有"车在哪、在做什么、能不能接任务"（ADR 0016），明文不泄露什么，几千台电脑什么都不用装就能打开。
  - 本机回环照旧走明文，给开发、测试和本机的测试系统用。
- **控制台用服务端自己生成的证书，那几台固定电脑各装一次**（产品负责人 2026-10-17）：
  - 安装时服务端生成一张证书，写上 factory01 的地址和机器名，有效期 20 年；钥匙存进 Windows 的密钥存储，和 ADR 0025 的服务端钥匙做法一样。证书生成后固定不变：电脑信任的就是这一张，不能像车载终端那张一样每次启动重新做。
  - 每台用控制台的电脑把证书文件双击装进"受信任的根证书颁发机构"一次。装在"当前用户"下不需要这台电脑的管理员权限，Windows 弹一个安全提示，点"是"。Chrome 和 Edge 都认这里装的证书。装过以后，打开控制台和普通网站一样，地址栏是锁，没有任何提示。
  - 这张证书只能证明 factory01 自己，不能拿去给别的网站签证书（RFC 5280；Chrome 源码也是这样核的）。所以装进去不会给这些电脑留下"别人能冒充任何网站"的口子。
  - 程序不用装：产品负责人笔记本上的 MCP 和值守 AI 在程序里认这张证书的指纹，和车载终端认服务端证书的做法一样（ADR 0025）。
- **证书到期前提前提示**（产品负责人 2026-10-17）：控制台上提前显示"证书 N 天后到期"，值守 AI 也报（ADR 0032 的值守报告）。提前多少天由实现票定。
- **仓库 `CLAUDE.md` 的 Safety 一节由实现票改写**：现行规则是"服务端接口有鉴权之前只听回环、只走明文"。登录（ADR 0045）做好以后，改成：要登录的接口只在本机回环和控制台的 HTTPS 入口上；厂区网上走明文的只有车辆一览页入口，它不收登录、只回车辆一览页；每个入口只听一块指定网卡的地址，不听全部网卡。改仓库 `CLAUDE.md` 要产品负责人在那张实现票的窗口里亲自确认；在那之前现行规则照旧有效。

## 出了问题怎么办

- 没装证书的电脑打开控制台地址，会看到整页红色的"您的连接不是私密连接"。这类电脑本来就不该用控制台，用车辆一览页。Chrome 允许点"继续前往"并记住一周；要告诉现场：看到这一页就是这台电脑没装证书，找人来装，别点继续。
- factory01 换了 IP 地址或机器名，或者证书和钥匙丢了（例如重装 factory01 又没备份），要重新生成证书，那几台电脑各重装一次。所以证书和钥匙都要备份；谁备份、放在哪里，归部署那张票，和 ADR 0025 的服务端钥匙一起定。
- 加一台用控制台的电脑，就在那台电脑上装一次证书，服务端和 factory01 上什么都不用动。

## 考虑过的做法

- **每台电脑都装证书**（初稿的建议）：几千台电脑不可能一台一台装。
- **请客户 IT 用厂里自己的证书体系签一张**：受 IT 管的电脑一台都不用装；但要和客户 IT 打交道，签发、续期都靠他们，客户有没有这套体系也不知道。只有固定几台电脑要用以后，它省下的工作量不大。
- **用公共证书机构（例如 Let's Encrypt）的免费证书，配一个某人自己拥有的域名**：所有电脑都不用装。但公共证书不能写内网 IP（2015 年起证书机构不再给内网名字和保留 IP 签证书），电脑必须用名字打开，名字解析多半还要找客户 IT；证书现在 90 天、2027-02-10 起 64 天、2028-02-16 起 45 天就要续，续期要么在 factory01 上装程序、放一把能改 DNS 的钥匙并让它出站上网，要么从别的机器自动拷到生产服务器上；续期失败或域名忘了续费，所有人的控制台一起停摆。
- **不加密，靠"工程师、管理员账号只认几台登记过的电脑（按 IP）"收窄**：什么都不用装；但班组长账号在哪台电脑上都能用，它的口令会在网上被看到，拿到的人能按继续、解除二类急停、取出货物交人工（开门）；登记过的电脑要固定 IP，同一网段里伪造 IP 也不是做不到。
- **用 Windows 自带的 SSH 客户端开加密通道（端口转发）到 factory01**：不用往证书库里装东西，服务端的登录入口可以一直只听回环。但每天要开着一个通道窗口，关了、睡眠、断网就断；每加、换、撤一台电脑都要改 factory01 上的 SSH 登记，等于动生产服务器；factory01 是 Windows Server 2016，没有微软自带的 SSH 服务，"只许转发、不许登录"的限制要实测。SSH 的钥匙和主机指纹本质上也是证书，只是不进证书库。
- **远程桌面登到 factory01，用那里的浏览器**：每个用控制台的人都要有一个能登录生产服务器桌面的 Windows 账号，能停服务、能看到上一代系统；不买远程桌面授权时最多同时 2 个人。
- **Windows 自带的 IPsec**：不用证书只能用预共享密钥，微软写明它是较弱的认证方式、只建议测试用，而且明文存在注册表里；factory01 厂区网卡的防火墙现在是关着的（ADR 0025），要打开，会牵连同一台机器上的上一代系统；出了问题很难查。
- **车辆一览页也走 HTTPS**：没装证书的几千台电脑都会看到红色警告。

## 后果

- factory01 上多两个端口（控制台入口、车辆一览页入口），一张要备份的证书和钥匙。factory01 厂区网卡的防火墙是关着的（ADR 0025），这两个端口和车载终端的端口一样对整个厂区网开放；要不要打开防火墙，仍由部署那张票定。
- "只有固定几台电脑用控制台"靠的是只有它们装了证书；服务端不按电脑限制谁能登录。别的电脑硬要打开控制台，会先看到红色警告；点了"继续前往"也能登录，但那条连接没有可靠的加密保护。
- 车辆一览页的地址建议用 IP 地址或不带点的短名字：Chrome 154（2026 年 10 月）起默认对没加密的"公网"站点先问一句再打开，IP 地址和不带点的名字不算公网；带点的内部域名会不会被问，没有核实（推断）。
- 每台用控制台的电脑都是 Chrome 或 Edge 时，上面的说法都核对过；Firefox 从 120 版起也默认认 Windows 里装的证书。
