# 移动单失败、被别人取消、挂起时，服务端先自己恢复，恢复不了再交人

SIMPLE 的移动单在车队调度系统里会出几种意外：失败（FAILED）、被别人在网页上取消、挂起（HANG，状态 9）。按 ADR 0008，服务端可以自己恢复它原本在做的事，前提是能读回证明条件和之前一样，并且有刹车。这几种意外在首个厂区都不少见（挂起大约每台车每天几次以下，被人误取消连着两次也不稀奇），每次都等人会让车频繁停在路上，所以都先由服务端自己恢复；恢复不了的，算车队调度系统故障，进故障处置（ADR 0012）。

## 决定

- 刹车用 ADR 0008 的那一条：同一张移动单 10 分钟内第 3 次又需要自动恢复，就停下，算车队调度系统故障，进故障处置。重建和从挂起继续，都要先满足 ADR 0009 的门锁条件。
- **失败**：车队调度系统的订单只会在刚创建、还没排队时变成失败，是它软件的问题，不是车坏了，此时车还在原地（产品负责人的说法，未实测）。服务端等 30 秒后在同一台车上重建。
- **被别人取消**：SIMPLE 没发过取消的移动单变成已取消，算误操作（产品负责人 2026-09-22）。服务端等 30 秒后在同一台车上重建，每次都在控制台提示。车上有货时，重建前先确认货还在原来的仓里：发现取消之后收到的新鲜读数里，每个装了货的仓光幕有货、门锁着；对不上就不重建，转故障处置。
  - 被挂起过的单之后被取消，也可能是误取消，照样重建；但重建前要先满足下面"自动继续"的全部条件，挂起的原因码是在 Matrix 上取消的也算不满足。条件不满足就不重建，在控制台提示，并直接算车队调度系统故障，告警给专业人员，由专业人员在故障处置中按"继续"触发重建（ADR 0012；产品负责人 2026-10-16）。
- **挂起**：车上的人在 Matrix（产品负责人口述的 AGV 车体自带系统的名称，车旁可以在上面操作）上按了取消、松了抱闸、行驶中断电又开机、充不上电，或车遇到故障没法继续，订单都会进挂起；服务端下发的急停不会，按车上的急停按钮也不会：行为实验室第 27、28 轮按住急停按钮约 15 分钟（520 个采样），订单一直是执行中、进度不动，车速 0，急停状态读 `CAN_NOT_RECOVER`，原先写的"按急停按钮会进挂起"由产品负责人 2026-10-18 按实测改正。挂起不会自己变成失败，出路只有继续或取消。"对挂起的单发取消，单子变成已取消"是产品负责人的说法，未实测。
  - **自动继续**：挂起期间，服务端持续核对条件，一满足就自动从挂起继续，不需要人按按钮。条件是：车上没有任何急停；车在线、已定位，车队调度系统没报车体故障；车载终端连着，门锁读数新鲜、全部锁着，门锁和光幕读数与服务端记录一致；车队调度系统给出的原因码不是充电失败、不是明确的车体故障，也不是在 Matrix 上取消。原因码给得不全，认不出原因时照常按条件判断。
  - **车旁的人**：控制台和这台车的车载终端上一直提示"订单挂起了"，告警给现场人员（ADR 0013）。车旁的人只做物理处理，例如把抱闸合上、断电后把车重新开机；处理好了，条件满足，服务端自己继续。（已改，见 ADR 0022：松抱闸算手动用车，不再自动继续，要班组长在故障处置中按"继续"。）车载终端上**没有**"继续"按钮。
  - **在 Matrix 上取消引起的挂起**：车旁的人的意思多半是别走了，服务端不自动继续，挂起一出现就直接算车队调度系统故障，告警给专业人员，由专业人员在故障处置中按"继续"（ADR 0012；产品负责人 2026-10-16）。进入故障时挂起的单已被取消，按下"继续"后服务端核对条件，按这一趟剩下的任务重建（ADR 0012）。"继续"只在故障处置里用。
  - **转成故障**：下面三种情况之一出现，算继续不了，变成车队调度系统故障，进故障处置：挂起超过一段时间（默认 10 分钟）还没继续成功；发了继续命令，订单一段时间（默认 30 秒）后仍是挂起（行为实验室见过"继续命令回成功、订单仍挂起"）；同一张移动单 10 分钟内第 3 次需要自动恢复（ADR 0008）。转成故障后，挂起的单随车进入故障被取消，按"继续"时按这一趟剩下的任务重建（ADR 0012）。不在挂起的第一刻就判故障：例如行驶中断电重启，头几十秒车还没重新定位、车载终端还没连回来，过一会儿多半能自己继续。
  - 充不上电引起的挂起不在本篇范围，留给充电的决定。（已定，见 ADR 0020：算充电失败，是车辆本体故障，进故障处置。）
- **状态 8**：含义未查明。别人的状态 8 订单 SIMPLE 不当作活单，读到就跳过：首个厂区的生产车队调度系统上积着约 252 张别的产线的状态 8 订单，把它们当活单曾在上一代引出读清单翻页读不全的缺陷。SIMPLE 自己的移动单变成状态 8 时，不重建，算车队调度系统故障，进故障处置。
- 上面的时长都放在厂区配置里。

## 考虑过的做法

- **失败记为车辆故障，人清故障后才重建**（上一代）：失败是车队调度系统软件的问题，偶发一次就要人，不值得。
- **失败第 2 次、被取消第 3 次分别交人**：失败和被取消都是车队调度系统那边的问题，第 2 次和第 3 次没有本质区别，统一用 ADR 0008 的一条刹车。
- **被取消后不设上限，每次都重建**：如果是某个程序在反复取消，车会一直循环下去，只能靠提示发现。
- **挂起过的单被取消，一律不重建、直接算故障**：它也可能是误取消；先核对挂起那套条件，满足就重建，人看到的提示和挂起是同一套。
- **挂起只告警，一律由人在车队调度系统网页上处理**（上一代）：挂起常见，多数是断电重启之类能自己过去的情况；现场人员也不该为此去网页上找车。
- **车载屏和控制台上都放"继续"按钮，谁都能按**：产品负责人不希望普通人员接触这个按钮；车旁的人做完物理处理，条件满足服务端自己会继续，用不着按钮。
- **挂起由服务端条件满足就继续，不区分 Matrix 上的取消**：车旁的人在 Matrix 上按取消，意思多半是别走了，自动继续会违背他的意思。
