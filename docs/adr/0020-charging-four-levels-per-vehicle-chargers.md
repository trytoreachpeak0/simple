# 充电只看四条电量线；车按自己的列表去桩，充不进电就是故障，桩由人停用

上一代的充电是规则最多的一块：约 40 条规则、十几个计时，另有"人工充电保持""清桩""只认结果码 407802 的充不上判据""桩和车双向隔离""原桩重充"等专门机制。2026-10-10 现场一台车进了人工充电保持，唯一的出口是出厂不显示的车载屏按钮，当晚收工，后来靠 SSH 到车上改配置才解开。产品负责人要求异常处理凭直觉就会、方式少而统一（2026-10-16），所以充电只留几条看得懂的电量线，出了问题一律走已有的故障处置（ADR 0012）和启用、停用（ADR 0011），不另立机制。

## 决定

### 四条电量线

- 电量只看四条线，都在参数配置里（ADR 0017），管理员能改；配置校验要求 紧急充电线 < 去充电线 < 可接活线 ≤ 充满线：

  | 线 | 默认 | 用在哪里 |
  | --- | --- | --- |
  | 紧急充电线 | 20% | 在等桩的车低于它，桩上的车高于去充电线就要让位；车低于它又没在充电、没在去充电的路上，就告警 |
  | 去充电线 | 35% | 空闲的车低于它就去充电；低于它的车不接新的一趟 |
  | 可接活线 | 60% | 正在充电的车过了它，有活就可以离桩接活；有车在等桩时，它要让位 |
  | 充满线 | 99% | 充到它，车就离桩去自己的等待点（ADR 0021） |

- 上一代的"任务后余量"和"每趟耗电"不再要：它们和强制线配合不好时会出现一段电量"搬运不让接、充电又说不需要"的死区，30/20/10 这组投运值只是凑巧没踩到。
- 充满线不定 100%：电池管理可能在 97%～99% 就停充，车队调度系统可能永远报不出 100%（推测，未实测）。所以充满线可调，下面"涨不动"的判据在可接活线以上也当作充满。
- **什么时候去**：空闲的车低于去充电线就去。车在跑一趟时跌破去充电线，不打断这一趟，照常送完、卸完再去；跌破之后这一趟不再接途中追加（ADR 0004），已经分给它、还没装货的任务照常去装。不顺便充电：电量在去充电线以上的车，没活、桩空着也不去，否则它在充到可接活线以前反而接不了活，去桩的路上有了活也改不了道（ADR 0021）。
- 正在充电的车，电量低于可接活线就一直充，不接活；到了可接活线以上，有活就离桩去接活，没活就接着充到充满线。
- 电量低是车不接新任务的第四种来由（ADR 0011 原有三种）：低于去充电线，或正在充电、还没到可接活线。控制台上这台车"现在能不能接任务"一栏写明原因，例如"电量低，充电中""电量低，等桩：1 号桩被故障中的 X 车占着""电量低，等桩：1 号桩被停用的 Y 车占着""电量低，没有可用的充电桩"，不另发告警（产品负责人 2026-10-16）。只有一个桩的项目，人从这一栏就能看出车为什么不接活。

### 车去哪个桩

- **按车配**：参数配置的车辆清单里，每台车写一个有先后顺序的"能去的充电桩"列表，每个桩按"地图 + 站号"写，和固定站点一样（ADR 0015）。SIMPLE 只认这些列表里出现过的站点是充电桩，不去地图上按名字或类型找。配置校验要求：每台车至少列一个桩；同一个桩不能出现在两个项目的车的列表里（不同项目各用各的桩，产品负责人 2026-10-16）；站点在地图上确实存在，之后被从地图上删了算配置故障。改一台车的归属项目时，它的列表要一起改成新项目的桩。
- **谁先、去哪个**：在等桩的车里电量最低的先，电量一样按车辆标识排。车按自己列表的顺序，去第一个空着的桩，不算路网距离：谁优先去哪个桩，写在列表前面即可。
- **排队只在 SIMPLE 里排**：车要充电、能去的桩都被占着时，先按空闲返回回自己的等待点（ADR 0021），在那里等，不建去桩的单；分到空着的桩，SIMPLE 才从等待点给它建去这个桩的移动单（产品负责人 2026-10-16：把空闲返回用到底，不新增规则）。已经停在自己等待点上的车就在原地等。单子先建了，车会开到一个被占着的桩前堵着，中途也改不了（ADR 0021 不取消自己的移动单）。
- **什么算占着**：只看本项目的车（产品负责人 2026-10-16）。启用的车在桩上或正开往桩，算占着；本项目里停用的车停在桩上，也算占着。别的产线、别的系统的车不看：要知道它们有没有在桩上或去桩的路上，只能遍历全部车辆和订单（产品负责人记得上一代调研过）。它们占着桩、让我们的车被交通管制挡住时，SIMPLE 不自己处理，挡住 10 分钟不动按 ADR 0008 算车队调度系统故障、告警，由人处理。
- 桩上的车离开了这个站点（车队调度系统车辆信息里的当前站点 `currentStation` 不再是这个桩；实验室见过车停在站外时它读 0，读哪个字段待实测，已记进 #11），才算桩空出来；只给它建了下一张单还不算，免得两台车在桩前碰头。

### 让位

- 车在等桩、它能去的桩全被占着时，桩上的车满足下面任一条就让位：
  1. 桩上的车已过可接活线：够用的车不该白占着桩。等桩的车都低于去充电线（"去充电"按钮不排队），所以不必再比它；
  2. 等桩的车低于紧急充电线，桩上的车高于去充电线：防止等桩的车电量耗尽；桩上的车要高于去充电线才让，被赶走的车自己才不会马上也要充。
- 让位的车离桩去自己的等待点，此刻有活就直接去接活；等它离开了桩，SIMPLE 再给等桩的车建充电单。离桩不用发命令：SIMPLE 只建这台车的下一张移动单，车队调度系统会在这张单最前面自动插入离桩动作（有过现场观测）。
- 开往桩、还没到的车也算占着桩，但不在路上被赶走（ADR 0021），到了桩上再按上面两条比较。
- 有没结束故障的车不让位：故障期间服务端不给它发任何移动单（ADR 0012）。
- 能让位的桩不止一个时，按等桩的车列表的顺序取第一个。
- 被让走的车之后如果跌破去充电线，就重新排队；那台抢到桩的车过了可接活线，第 1 条又会让它把桩让回来，不会有车一直排不上。上一代曾把"可插队"改成"占了不可抢"，原因在调研材料里没找到；这里的两条都靠电量线隔开，不会两台车来回抢。

### 充电失败

- **判据只有一个**：车到了桩上，任何连续 10 分钟里电量涨不到 3 个百分点，算"涨不动"；车队调度系统把充电单挂起、原因码是充电失败（目标站不能充电时是结果码 407802，实验室测过），也直接算，不等满 10 分钟。上一代"到桩 30 秒没读到充电""非充电状态持续 60 秒""稳定 3 分钟后 10 分钟内涨不到 3%""407802 连续两次"四套判据，最后都会表现成涨不动，不再分别去认。10 分钟和 3 个百分点放在参数配置里。
- **涨不动时看电量**：在可接活线以上，当作充满了，照充满处理，不告警；在可接活线以下，算充电失败，是这台车的车辆本体故障，交给班组长走故障处置（ADR 0012）。服务端不分辨是车坏了还是桩坏了，也不自己重试、不自动换桩：原因不明，按 ADR 0008 证明不了条件和之前一样，就停下交人。车和充电桩由同一个厂家修，故障标签都是车辆本体故障（产品负责人 2026-10-16）。
- **故障期间**：车停在桩上就地处置（ADR 0012），不接新任务，不让位；它占着这个桩，别的车也不会被派来。处置的出口照旧：
  - **继续**：没结束的充电单在车进入故障时已被取消（ADR 0012）。车还在原来的桩上、原桩也没被停用，就在原桩重建一张充电单接着充；车已经不在桩上（被挪走了），或原桩已被停用，就按上面的排队流程走：回自己的等待点，分到空桩再去（产品负责人 2026-10-16）。10 分钟"涨不动"的窗口从按下"继续"那一刻重新算。
  - **停用这台车**：交给人，例如人工充电（见下）。
- ADR 0010 把"原因码是充电失败的挂起"留给了本篇，就按上面处理。去充电的单出了别的意外（失败、被别人取消、别的原因的挂起、状态 8），和搬运的移动单完全一样按 ADR 0010 和 ADR 0008 的刹车处理（产品负责人：去充电、去等待点本质上都是车队调度系统的订单，2026-10-16）。

### 充电桩停用

- 班组长及以上随时可以在控制台停用一个充电桩，故障处置中也可以；停用的桩不分给任何车，直到工程师及以上在控制台重新启用（ADR 0014："宣布修好、重新投入使用"归工程师）。停用不赶走正在桩上的车。
- 充电桩停用和车辆启用一样是人按的开关，不是配置，不随配置导入、修改或退回而变；新加进列表的桩是可用的。停用的桩仍留在各车的列表里，所以"每台车至少列一个桩"的校验照旧通过。
- 服务端从不自己停用桩。

### 防止电量耗尽

- 只有一条告警：启用的车电量低于紧急充电线，又不在充电、也不在去充电的路上，就告警，写明原因，例如"能去的充电桩都停用了""1 号桩被故障中的 X 车占着""车上有货，在卸货站等人""正在跑一趟"。它不是故障，按 ADR 0013 和 0014 先给车旁的人，30 分钟没解决升级给班组长。车停着不动时掉电很慢，真会耗尽，是因为一直没人知道。
- 人能做的都是已有的动作：车旁的人把货卸掉，班组长处置占着桩的故障车、停用这台车交人工充电，管理员给它多列几个桩。
- 它取代上一代"车上有货等人时低于 15% 只告警"那一条；产品负责人 2026-10-10 定的"不带货去救命充电"照旧。
- 列表里的桩全被停用时，"现在能不能接任务"一栏写"电量低，没有可用的充电桩"（见上面"四条电量线"），不另发告警；电量跌破紧急充电线时由上面那条告警写出这个原因。

### 人工充电就是停用

- 不设"人工充电"状态。要给一台车人工充电，班组长先在控制台停用它（ADR 0011，车上没货才能停用），人拿手动充电器去充，充多少、充多久由人定；充好后工程师启用，启用前照常核对（ADR 0011）。SIMPLE 不需要知道停用的车是在人工充电、在维修还是被挪走了。上一代 2026-09-15 定的"人工充电不替代自动充电，只是故障时的兜底"照旧，所以每次启用都要找工程师的代价不大。
- 没停用就直接推去人工充电的，按 ADR 0022 的手动用车处理。
- 启用一台车时，它正停在自己列表里的桩上、而且在充电，就直接算"充电"用途，之后照常按可接活线、让位、充满线走；所以它在充电不算手动用车的迹象（ADR 0022）。

### 控制台的"去充电"

- ADR 0018 把"送车去充电"留给了本篇。控制台上有"去充电"按钮，班组长及以上能按，只在车启用、没有没结束的故障、空闲（没有用途）、电量还没到充满线时出现。它只是"让空闲的车先去桩上充着"：过了可接活线有活照样离桩去干活，所以不保证充满。平时多半用不到（产品负责人 2026-10-16）。
- 按下时，车列表里有一个此刻空着、没停用的桩，就立刻给它建去这个桩的移动单，之后和普通充电完全一样（可接活线、让位、充满去等待点）；没有，就提示"能去的充电桩都被占用"，车不动、不排队，人可以过会儿再按。每次按都记进事件记录（ADR 0019）。
- 不设别的让车去充电的入口；车什么时候自己去充电，只看四条线。

### 车队调度系统的行为

- 有过观测（上一代的行为实验室和现场记录，样本少）：充电单是"移动到桩 + 充电动作"，车一开始充电，单子自己就变成成功、结束了，车在没有订单的情况下继续充；下一张单开始执行时，车队调度系统自动在它最前面插入离桩动作，上一代从没为结束充电取消过订单。目标站不能充电时结果码是 407802、订单进挂起。车在充电桩上充电、插着手动充电器时，车辆信息里的 `batteryState` 都报 `CHARGING`。
- 推测，未实测，已记进 #11：电池管理可能不到 100% 就停充。

## 考虑过的做法

- **只留两条线（去充电线 30%、充满线 80%）**：充满线定低了车只充八成、很快又要回来；定高了车一两个小时困在桩上，有活也不接。所以加可接活线。
- **沿用上一代的四条线加三个参数（余量、每趟耗电、稳定期、窗口、最小增量）**：有死区，人也算不清车为什么不接活。
- **只用"可接活线"判断让位**：桩上的车才充到 40%、外面的车只剩 12% 时不让，等桩的车可能耗尽电量。
- **只用"紧急充电线"判断让位**：不防白占，低于去充电线的车可能等一台早已够用的车充到 99%，这段时间它也接不了活。
- **占了桩就不可抢**（上一代）：桩上的车充满不走时，别的车等桩没有出口。
- **充电桩按项目配，本项目的车都能去本项目的任何桩**：做不到"A 车只去 1、2 号，B 车只去 3 号"。
- **项目和车两处都配桩**：一件事两处写，迟早对不上；按车配加一条"不能跨项目"的校验就够了。
- **空桩有多个时去路网上最近的**（上一代）：要向车队调度系统要路径距离，算不出时还得另定办法；列表顺序人一眼看得懂。
- **先给排队的车建单，让它开到桩前等**：车堵在桩前，中途有了活或别的桩先空出来也改不了。
- **等桩的车停在原地等**：可能堵在卸货站前；回自己的等待点等，用的是已有的空闲返回。
- **充电失败后先自动换一个桩试，换过去能充就停用原桩，也充不上就判定是车的问题**：能自动隔离坏桩，但服务端要猜是车还是桩，判断过程人看不懂；产品负责人嫌复杂，要服务端不去分辨（2026-10-16）。
- **充电失败直接自动停用这个桩**：车的充电触点坏了时，它去一个桩停一个，会把好桩挨个停掉；产品负责人不接受错停。
- **不设充电桩停用，坏桩由管理员从配置里删掉**：只有管理员能改，夜班没人；只列了这一个桩的车删不掉。
- **上一代的清桩、桩暂停、车充电资格暂停**：人看不见、解除要另调接口，正是要删的机制。
- **保留"人工充电"状态，控制台和车载屏都能解除**：多一个状态和一套进出规则；停用已经表达了"这台车现在归人"。
- **"顺便充电"：没活、桩空着就去充**：车在充到可接活线前接不了活，去桩的路上有了活也改不了道，反而耽误送货。
- **"去充电"按钮在桩被占时排队**：按的人不知道车什么时候会走；不排队，占着就提示，人看得懂。
- **不设"去充电"按钮，只靠电量线**：产品负责人要留一个手动入口，让空闲的车先去桩上充着。
