# 控制台上的"急停这台车"是二类急停，SIMPLE 不自动解除它；车队调度系统网页上的操作不搬进控制台

上一代没有"控制台对选中的车下急停"的入口，人不在车旁时只能去车队调度系统网页上下。产品负责人要在控制台加一个"急停这台车"按钮（2026-10-16）。它是人在控制台上下的，不是服务端为自己的停车原因下的，所以按二类急停对待：三类急停仍只用于行驶中门锁未证明锁闭（ADR 0009），不扩大。但服务端知道这个急停是控制台下的，不能像它自己的三类急停那样一看条件满足就解开。

## 决定

- **谁能按**：班组长及以上（ADR 0014）。按下后服务端在车队调度系统里对这台车下急停，记进事件记录，控制台和这台车的车载终端上提示。它不算故障，不进故障处置；告警按"车被下了二类急停"处理：先给车旁的人，30 分钟没解决升级给班组长（ADR 0013、0014）。
- **SIMPLE 不自动解除它**。车队调度系统里几种急停共用同一个锁定，ADR 0009 接受过"SIMPLE 解除自己的三类急停时可能连带解开别人的急停"；对控制台下的这个急停，服务端有自己的下达记录，所以它还在时，SIMPLE 不自动解除三类急停，免得顺手把它解开。
- **按二类的规矩解除**：控制台和车载终端上的"解除二类急停"入口能解，不限人（ADR 0009）；在车队调度系统网页上解开的，服务端读回后也算解除。按下解除入口时，车上没有三类急停就解开锁定；还有三类急停时，控制台急停就此撤掉，锁定按三类的规矩留着或自动解除，入口照 ADR 0009 显示三类急停的原因。
- **接受的风险**：车旁的人在车载终端上按一下"解除二类急停"，就能解开控制台下的急停。这是二类急停的本意，产品负责人确认接受（2026-10-16）。要保证车停住，只能按车上的急停按钮（一类，软件解不开）。
- **车队调度系统网页上的操作不搬进控制台**：挪车、改地图、调避障留在车队调度系统网页上做；SIMPLE 只察觉这些变化（车位置突变、站点名变了、出现外来单）并记进事件记录、显示在控制台上。启用的车要人工挪，先停用（ADR 0011）。解除急停、取消外来单已有 SIMPLE 自己的出口（ADR 0009、0011），送车去充电留给充电的决定。

## 考虑过的做法

- **不加按钮，要停车就按车上的急停按钮或去车队调度系统网页下**：做得到的程度一样，但人不在车旁时要切到另一个系统去找车。
- **按下即手动判定故障加立即急停，只能用"继续"或停用车解除**：比二类牢靠，但三类急停的用途变宽，人也要把急停和故障处置连起来理解；产品负责人要三类只限于 ADR 0009 的范畴。
- **按普通二类对待，SIMPLE 照常自动解除自己的三类急停**：门锁一正常就可能把它连带解开，按了等于没按。
- **控制台下的急停在车载终端上解不开**：车旁的人碰出来的、确认安全了的停车也得等控制台的人，和二类急停"就地解除"的本意相反。
- **把挪车、改地图、取消订单、送车去充电搬进控制台**：要在 SIMPLE 里重做车队调度系统的功能；需要 SIMPLE 管的几样已经各有出口。
