# 每台车配自己负责的任务类型和一个派车区，一个任务类型只归一台车，派车不选车

首个厂区的客户要求三台车按任务类型专车专用，一类任务只给一台车（产品负责人 2026-10-10）。前几场只定了一条需求落在哪个项目、哪个派车区（ADR 0002、0006、0015），参数配置里也只有"每个项目每个任务类型的开关"（ADR 0017），没有"哪台车接哪些任务类型"，派车区"带一套自己的派车策略"的说法也一直没有内容。产品负责人定：每台车固定负责几个任务类型，一个任务类型不会同时在几台车上（2026-10-16）。这样一条需求该给哪台车由配置直接定，派车不需要选车策略。

## 决定

- 参数配置的车辆清单里，每台车写它负责的任务类型（ADR 0017）。
- 同一个项目里，一个任务类型只归一台车；两台车配了同一个任务类型，配置校验不通过。项目里开着的任务类型没有配给任何一台车，配置校验也不通过；配给了一台停用的车不算没配，需求照常等着（产品负责人 2026-10-16）。
- 一条需求给本项目里负责这个任务类型的那台车，派车不选车。派车区不带选车策略：它是一块收货范围，定需求归哪个项目（ADR 0015），一趟车只在一个派车区里收货（ADR 0004）。
- **每台车只属于一个派车区**：车辆清单里每台车配一个派车区，车只接这个区的需求，听这个区的需求先后策略（产品负责人 2026-10-16）。代价：一台车不能同时服务两个区，要换区只能改配置。
- 配置校验：车的派车区要属于车所属的项目（ADR 0015）；车负责的任务类型，需求都要落在车的派车区里（产品负责人 2026-10-16）。需求落在哪个派车区，按机台那一端的区域号归哪个派车区定，固定站点那一端不参与（ADR 0006、0015）。一个任务类型的需求会出在哪些区域号上，要到 MES 里出现需求时才知道，配置里没有这项，所以这一条配置时判断不了。
- **需求落在负责车的派车区之外**：运行时出现一条需求，负责它这个任务类型的车不服务它所在的派车区，就不派车，在控制台清单里列出并写明原因（例如"T 类归 X 车，X 车只服务 A 区"），同时算一次配置故障（不属于任何项目，告警等管理员处理，ADR 0015），和"区域号没配派车区：不派并告警"一样处理（产品负责人 2026-10-16）。这一定是配置错了（区域号划错了区，或任务类型配错了车），要有人改配置才能解决。配置改好后照常派（ADR 0003），配置故障按 ADR 0008 自动结束。
- 这台车停用、有没结束的故障或电量低，接不了新任务时，这类需求等着，不换给别的车，与 ADR 0003 的不改派一致。分配给车之前它只是需求（ADR 0003），从 MES 消失就不写抑制。
- 改一台车负责的任务类型只影响之后的新需求，已分配的任务照原来做完（ADR 0003、0017）。
- **需求先后策略**：同一台车同时有多条需求可接时先接哪条，是派车区的一个参数，放在参数配置里（ADR 0017）；车听自己所属派车区的。可选的至少有按需求出现的时间、按距离，以后可以加别的指标（产品负责人 2026-10-16）。默认取哪一种，另定。（已定，见 ADR 0036：第一版做四种，默认最近优先，只用于从机台取货的任务类型。）

## 考虑过的做法

- **几台车都能接同一类需求，由派车区的派车策略选车**：要另定选车规则（谁近、谁电量高、正在充电的车和等待点上的空闲车谁先），而客户要的是专车专用，用不上。
- **需求落在负责车的派车区之外时，只在控制台列出、不告警**：人看得到原因，但配置错了没人被叫去改，会一直列着。
- **把"同一项目里一个任务类型只归一台车"放宽成"同一派车区里只归一台车"，让别的区另配一台车接这类任务**：等于放宽专车专用，又回到一类任务分在几台车上。
- **车不固定派车区，先选去哪个区，再按那个区的需求先后策略选需求**：一台车能服务几个区，但多一层规则（产品负责人 2026-10-16）。

## 后果

- #12 评论里"正在充电的车和等待点上的空闲车谁先接活"的问题不会出现。
- 一台车只服务一个派车区；一个项目有几个派车区时，每个区都要有自己的车，换区只能改配置。
- 负责某类任务的那台车停用、故障或在充电时，这类需求没有别的车接，由人工送货兜底（ADR 0003）。
