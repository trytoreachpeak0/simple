# 任务结束后同一需求永久不再派

一条需求被受理成任务后，无论任务怎么结束，同一需求业务键永久不再派，也不放回待派重试。前提是：现场一直有人工送货兜底，机器人只是辅助，漏派一单不会造成问题；而重复派车、派车去拉已经不在的货，会浪费车辆、干扰现场。所以 SIMPLE 宁可漏派，也不为"一单不丢"付出复杂度。首个厂区的情况是：车少、送货需求多，客户把这套系统定位为辅助人工；现场人员按自己的节奏送货，看到机台上有货就拉走，不等机器人。

## 决定

- 所有结局都写抑制：送达、操作员取消、故障货物交接、站点超时、持货超时离站、途中需求从 MES 消失、放弃重建。需求在被受理之前从 MES 消失，不写抑制，以后再出现照常派。
- 抑制只落在等不到人的那一站：离站期限内没装上的那几条需求被抑制；同一趟里其他站的需求不受影响，车继续前往。
- 改派（还没装货的任务从一台车转给另一台车）不算任务结束，不写抑制。
- 不提供"解除抑制"的操作：等有人想到要解除时，货多半已被人工搬走，解除反而可能让车去拉不存在的货。
- 抑制永久有效。旧记录可以按时间清理，效果等同永久。

## 途中需求从 MES 消失

- 连续两次完整读取 MES 都看不到这条记录，才算消失；误判的代价只是漏一单或白跑一趟，所以不需要更长的去抖。
- 以取货站第一次扫码通过为界：之前消失，撤掉这个任务并写抑制，同一站还有别的需求就照去，没有了才撤掉这次停靠；之后消失，货已在人手里或车上，照常送到。装货时现场有人顺手在 MES 上登记过站，就可能出现后一种情况，概率很小。
- 扫码之后操作员又取消装货，按操作员取消处理，照样写抑制。

## 考虑过的做法

- **只有人明确取消和故障货物交接才抑制，其余结局后可再派**（上一代需求基线的原意，也是调研的建议）：SIMPLE 不写 MES，送达后 MES 记录要等现场登记过站才消失，"送达后可再派"会重复派车。
- **站点超时、持货超时放回待派，满次数才终结**（上一代系统 2026-10-14 的决定）：为"不丢单"增加了重试和计数，而现场有人工兜底，这份复杂度不值得。
- **抑制到 MES 记录稳定消失为止**：能接到返工、退回工序后再出现的货（极少），但要靠去抖判断"消失"；MES 网关一旦出错、一段时间读不全记录，大批抑制会被误解除，已送过的货被成批重新派车，正好违反"宁漏不重"。

## 后果

上一代系统也是"受理过就永不再派"，当时被看作丢单的根源：换库、试跑数据、MES 抖动都会让需求再也派不出去。在"有人工兜底"的前提下，这些丢单是可以接受的代价。为了让兜底的人看得到，每个任务的结局和原因都进服务端的事件记录，控制台另有一份"机器人已放弃、MES 里仍挂着"的需求清单，人工送走、MES 登记过站后自动消失；不做主动告警。如果将来某个厂区没有人工兜底，这篇 ADR 需要重新评估。
