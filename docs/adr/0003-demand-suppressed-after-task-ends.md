# 任务结束后同一需求永久不再派

一条需求被受理成任务后，无论任务怎么结束，同一需求业务键永久不再派，也不放回待派重试，所以一条需求最多形成一个任务。前提是：现场一直有人工送货兜底，机器人只是辅助，漏派一单不会造成问题；而重复派车、派车去拉已经不在的货，会浪费车辆、干扰现场。所以 SIMPLE 宁可漏派，也不为"一单不丢"付出复杂度。首个厂区的情况是：车少、送货需求多，客户把这套系统定位为辅助人工；现场人员按自己的节奏送货，看到机台上有货就拉走，不等机器人。

## 决定

- 任务的每一种结局都写抑制。结局和各自结束的任务如下：
  - **送达**：货卸到目的地，结束这个任务。
  - **操作员取消**：操作员在车旁取消装货，结束被取消的那个任务；扫码之后再取消也一样。
  - **故障货物交接**：车出故障，人把车上的货取出接手，结束货被取出的那些任务。
  - **站点超时**：车在取货站，离站期限到了，这一站还有任务的货没装上，结束这一站这些没装上的任务。
  - **持货超时**：车在取货站持货等单，持货期限到了就离站，结束这一站还没开始装货的任务。（已取消，见 ADR 0004。）
  - **途中从 MES 消失**：见下一节，结束消失的那个任务。（已取消，见 ADR 0021：需求受理后从 MES 消失不再结束任务。）
  - **控制台放弃**：人在控制台放弃一个任务（例如在等车恢复的任务），结束这个任务（只限车上还没有这条任务的货，见 ADR 0005）。
- 抑制只落在上面列出的任务上。站点超时和持货超时（已取消，见 ADR 0004）只结束这一站的任务，同一趟里其他站的任务不受影响，车继续前往。
- 需求在被受理之前从 MES 消失，不写抑制，以后再出现照常派。
- 受理就是把需求分配给一台车（产品负责人 2026-10-16）。分配之前都只是需求：一趟装不下（ADR 0005）、区域号没配开门侧或派车区（ADR 0006、0015）、落在负责车的派车区之外（ADR 0023）的需求只在控制台列出，配置改好了照常派；从 MES 消失了不写抑制，同时从清单里消失。
- SIMPLE 不改派：任务从分配给一台车起到结束，都跟着这台车。车在装货前不能服务（故障、等桩充电、离线）时，任务继续挂在这台车上，车恢复后接着做；控制台显示"在等车恢复"，人可以在控制台放弃它。在同一台车上重建车队调度系统的订单不是改派。在控制台改配置让另一台车接某类任务（即改车辆清单里车负责的任务类型，ADR 0023），只影响之后的新需求，不挪动已分配的任务。
- 部分装货的处理另定（已定，见 ADR 0005）。
- 不提供"解除抑制"的操作：等有人想到要解除时，货多半已被人工搬走，解除反而可能让车去拉不存在的货。
- 抑制永久有效。抑制记录先不清理，清理规则以后单独定。

## 途中从 MES 消失

（本节已作废，见 ADR 0021：需求一旦受理成任务，MES 里消失不消失都不影响它，车照常去，没人扫码就以站点超时结束；服务端不为此取消开往取货站的移动单。）

- 在所有查询都成功的连续两份 MES 快照里都没有这个需求，才算消失；误判的代价只是漏一单或白跑一趟，所以不需要更长的去抖。
- 以取货站第一次扫码通过为界：之前消失，撤掉这个任务并写抑制，同一站还有别的任务就照去，没有了才撤掉这次停靠；之后消失，货已在人手里或车上，照常送到。装货时现场有人顺手在 MES 上登记过站，就可能出现后一种情况，概率很小。
- 在等车恢复期间消失，同样撤掉任务并写抑制，所以车恢复后不会白跑。

## 考虑过的做法

- **只有人明确取消和故障货物交接才抑制，其余结局之后可再派**（调研的建议）：SIMPLE 不写 MES，送达后 MES 记录要等现场登记过站才消失，"送达后可再派"会重复派车。上一代需求基线的原文与此不同：四种本地取消（含站点超时）和故障货物交接都写抑制，只有送达和 MES 消失不写；它同样有送达后重复派车的问题。
- **站点超时、持货超时放回待派，满次数才终结**（上一代系统 2026-10-14 的决定）：为"不丢单"增加了重试和计数，而现场有人工兜底，这份复杂度不值得。
- **抑制到 MES 记录稳定消失为止**：能接到返工、退回工序后再出现的货（极少），但要靠去抖判断"消失"；MES 网关一旦出错、一段时间读不全记录，大批抑制会被误解除，已送过的货被成批重新派车，正好违反"宁漏不重"。
- **车不能服务时改派给别的车**：客户现场不需要；任务跟着车走更自然，也不会出现改派后被自己的抑制挡住的问题。

## 后果

上一代系统也是"受理过就永不再派"，当时被看作丢单的根源：换库、试跑数据、MES 抖动都会让需求再也派不出去。在"有人工兜底"的前提下，这些丢单是可以接受的代价。为了让兜底的人看得到，每个任务的结局和原因都进服务端的事件记录；控制台另有一份"机器人已放弃、MES 里仍挂着"的需求清单，只列没送达就结束的任务和部分送达的任务（见 ADR 0005），人工送走、MES 登记过站后自动消失；不做主动告警。如果将来某个厂区没有人工兜底，这篇 ADR 需要重新评估。
