# 值守 AI 用只能看的值守账号，管理员一个开关暂停它，跑在产品负责人的笔记本上

ADR 0032 定了第一版有值守 AI、它只看只报告。它和产品负责人叫来的 AI 会话不同：没人盯着，凭据要长期放在它跑的机器上。所以要定它用什么账号、人怎么一下叫停它、它跑在哪。仓库 `CLAUDE.md` 从旧测试工具继承的"一个 `HALT` 文件停掉所有自动动作"，在生产上指什么也一并定下。跑在哪是技术题，先调研几套方案、讲清现场后果，再由产品负责人挑（2026-10-17）。

## 决定

- **值守账号**（产品负责人 2026-10-17）：
  - 整个 SIMPLE 只有一个，由管理员在控制台账号页上建、改密码、删，和其他账号一样（ADR 0016）；
  - 看得到的和管理员一样：全部项目的车、任务、告警、事件记录、统计、当前配置和程序日志（ADR 0034）。要看全部项目，是因为不属于任何项目的故障（MES、MES 网关、服务端、配置）也在它要看的范围里；
  - 一个动作都按不了，经控制台登录也一样，MCP 用它也只能看；
  - 它不属于任何角色。三级角色（ADR 0014）对的是客户技术协议的"操作、技术、工程"三级权限，原样不动；
  - 值守 AI 用它，以后只需查看全厂的人（例如来查问题的客户 IT）也可以用，所以名字不带"AI"；
  - 它不按按钮，事件记录里不会出现它做了什么（事件记录只记变化和动作，ADR 0019）。
- **暂停值守**（产品负责人 2026-10-17）：
  - 管理员在控制台账号页值守账号那一行有一个"暂停值守"开关；谁、什么时候开关的记进事件记录。值守 AI 每一轮先读它，开着就不看生产、不写报告；
  - 跑值守 AI 的那台机器上的 `HALT` 文件意思一样，是服务端连不上时的备用；
  - **只停 AI，不停服务端自己的停下、重试和恢复**（ADR 0008）：往安全方向的动作绝不能因为谁叫停了 AI 就不做。仓库 `CLAUDE.md` 说的"`HALT` 停掉所有自动动作"指的是 AI 的动作；
  - 产品负责人自己叫来的 AI 会话不归这个开关管，关掉会话就停了；
  - 同一行显示**值守 AI 最后一次来看的时间**：服务端知道值守账号最后一次来读是什么时候，不用 AI 写任何东西。它和值守日报（ADR 0032）一起，让人分得清"没报告"是一切正常还是值守 AI 停了。
- **跑在产品负责人的笔记本上**（产品负责人 2026-10-17）：
  - 每 15 分钟用 Claude Code 的无头方式起一次。先只看上次之后新出的告警、事件和程序日志，用便宜的模型；有新情况，再换强一点的模型细查，写值守报告；
  - 它只拿到两样工具：用值守账号只读访问服务端（经服务端接口或只读的 MCP，MCP 只是接口上的薄壳）；只能在 SIMPLE 仓库开 issue、写评论的 GitHub 凭据。命令行、改文件、推代码一概不给；
  - 这两份凭据单独放，不和产品负责人自己的管理员凭据混在一起。漏了，拿到的人只能看生产、只能在公开仓库开 issue；
  - 费用走产品负责人现在的 Claude 订阅（产品负责人 2026-10-17）。
- **上岗前要先有的东西**（都归实现票）：服务端接口的鉴权（控制台要在厂区网里用，本来就要做，仓库 `CLAUDE.md` 的 Safety 一节）；值守账号和暂停值守开关；只读的值守入口；程序日志（ADR 0034）。

## 后果

- **笔记本开着、没睡眠时才有值守**。合上盖子的那段时间，日报会少次数，"最后一次来看的时间"会停住，一看就知道。
- **和产品负责人自己的会话抢同一份订阅用量**：一天约 96 次调用。哪天开的会话多、用量用满，值守也跟着停；反过来，值守也挤掉干活的余量。日报里看得出它停了。
- **笔记本内存本来就紧**，每 15 分钟起一次会多占一点；真卡了再调频率。
- 笔记本不跑 CI，没有"凭据放在跑 PR 代码的机器上"的问题。

## 考虑过的做法

调研于 2026-10-17 读了现场机器的记录和 Claude Code 的官方文档。

- **值守 AI 借管理员账号、靠 MCP 那边设成只读**：只读只是 AI 那一侧自己守的规矩；凭据长期放在无人看守的机器上，一漏，拿到的人登录控制台什么都能做（ADR 0016 已记过这个风险）。ADR 0016 也否掉过"给 AI 单独开一个和管理员同级的账号"。
- **借某个项目的班组长账号**：只看得到一个项目，漏了能按停车、继续、取货。
- **值守账号做成三级之下的第四级角色**：要改 ADR 0014 和客户三级权限的对应关系；它一个动作都没有，当成角色没有意义。
- **只靠 `HALT` 文件叫停**：要远程登录那台机器建文件，不是"点一下就停"。
- **叫停也停服务端的自动恢复**：服务端往安全方向的动作不能停（ADR 0008）。
- **跑在 factory01（生产服务端那台）上**：factory01 是 Windows Server 2016，Claude Code 要求 Windows Server 2019 或更新。
- **跑在 simple01 上**：常开、在厂区网里，但它跑 CI（PR 的代码），走 Wi-Fi，防火墙全关，上 GitHub 走笔记本的代理。产品负责人选了笔记本。
- **Anthropic 云端的定时任务或 GitHub 自带的机器**：连不进厂区网；要让 factory01 往外推数据，就要在生产服务器上装新程序、放 GitHub 写权限，生产事实也要先出厂。
- **不定时，等服务端的检查出事再叫 AI**：告警没有往外推的渠道（ADR 0013），"出事时叫 AI"还是要有人去轮询告警栏，等于定时看，只是看得更少。
- **单独的 API 账户、设每月上限**：费用单独记账、不占订阅用量；产品负责人选了用现有订阅。
