# 控制台以地图页为首页，一台车的一切都在车辆详情里

第四场（ADR 0013～0016）定了控制台上谁能做什么，这一篇定控制台长什么样：有哪些页面，人在哪里看、在哪里按。最高原则是产品负责人 2026-10-16 定的"凭直觉就会、不用专门学；方式少而统一"：页面少，同一类东西只在一处，界面直接告诉人现在能按什么、为什么不能按。

初稿以车为中心：首页每台车一张卡片，点进去是车辆页，另有需求、记录、配置、账号几页。产品负责人要更直观的（2026-10-17）：一张可以拖动的地图，上面显示车、机台、哪些机台有任务，点车或机台显示相关信息，还要看得出车接任务的逻辑。

车队调度系统能给的地图数据够画这张图，这一点查过：车的坐标（毫米）和朝向；每张地图上每个站点的坐标；站点之间的连线，包括弯道。RIoT 行为实验室第 44 轮录下的生产地图（26 号图）有 208 个站点、415 段路径（其中 21 段是弯道），约 84 米 × 88 米。上一代为算路线读过这些数据，但从没画出来过。墙和货架这类底图，接口文档里有一个下载地图图片的接口，从没调用过，格式不明。

现场看控制台的只有电脑，而且有很多台（产品负责人 2026-10-17）：同一个项目的账号会同时在几台电脑上开着、一直登录着（ADR 0016）。

## 决定

- **只做电脑浏览器**，不做手机和平板适配。
- **页面一共五个**，顶上一排导航（产品负责人 2026-10-17）：

  | 页面 | 给谁 | 放什么 |
  | --- | --- | --- |
  | 地图页（首页，登录后先到这里） | 所有账号 | 本项目的地图和车，上方是告警栏，点东西看详情 |
  | 需求清单 | 所有账号 | 没能分配的需求和原因（ADR 0003、0005、0023）；机器人已放弃、MES 里仍挂着的需求（ADR 0003、0005） |
  | 记录与统计 | 所有账号 | 统计和事件记录（ADR 0019） |
  | 配置 | 所有账号能看，管理员能改 | 整份参数配置（ADR 0017） |
  | 账号 | 只有管理员 | 建账号、改密码、删账号（ADR 0016） |

  不另设车辆页、任务页、告警页、故障处置页：同一台车的事散在几页里，人就得来回跳。另有不用登录的车辆一览页（ADR 0016），见最后一条。
- **地图页**：
  - 画出路网（站点和连线，含弯道），可以拖动、缩放；标出机台（区域号对应的站点，ADR 0002）、固定站点、充电桩、等待点和本项目的车。
  - 车显示位置和电量，颜色表示状态：正常、不能接任务、有没结束的故障。
  - 有需求的机台标出来，分"还没派"和"已给了车"两种。
  - 选中一台车时，按顺序画出它接下来要去的站。
  - 只画本项目的车和站（ADR 0015）。一个项目的车跨几张地图时，按地图切换。
  - 管理员不属于任何项目，看到的是这张地图上所有项目的车和站，标明属于哪个项目，可以按项目筛选；告警栏里是所有项目的告警，每条标明项目。
- **点车、点机台、点充电桩，显示它的详情**。详情里每台车、每条需求都用一句话说明"为什么"，这就是产品负责人说的"车接任务的逻辑"：
  - 车：在做什么、为什么，接下来去哪几站；不能接任务的写明原因（ADR 0011、0020）。
  - 需求：给了哪台车、排在这一趟的第几站，或者为什么还没派（ADR 0003、0005、0023）。

  这些原因都是现行规则本来就要服务端给出的，这里只是把它们放到地图上，不新增规则。
- **车辆详情**是一台车的全部信息和能按的全部动作所在的地方：
  - 状态和"为什么"、电量、仓位和门锁、车上的任务、它的告警；
  - 车载屏此刻给车旁的人的指示（例如"请取出 3 号仓的货，取完关门"），让控制台的人知道车旁的人正被要求做什么；
  - 现在能按的全部动作，按法见 ADR 0030；
  - 最近的事件，下面有"看全部"，跳到记录与统计页并筛好这台车。
- **故障处置不做向导**（产品负责人 2026-10-17）。车一进入故障，车辆详情最上面写明是什么故障（例如"3 号仓位故障：发了开锁请求，锁反馈没变成开"），下面直接列出 ADR 0012 的全部出口：继续、取出货物交人工、单独打开出故障的仓门检修、停用仓位、放弃没装货的任务、停用车。能按的每个写一句"按了会怎样"，按不了的变灰并写原因（例如"继续：抱闸松着"）。出口没有固定顺序，有时先取货再停用车，有时直接继续，向导要么替人定顺序，要么分支多到要人去学。
- **待确认的车载电脑**（ADR 0007、0025）显示在它自称的那台车的车辆详情里："有一台车载电脑等待确认为这台车，配对码 482193"，工程师核对车载屏上的码一致后按确认；地图上这台车的图标加一个标记。它自称的车辆标识不在车辆清单里的，列在配置页车辆清单上方的"不认识的车载电脑"里，等管理员先把车加进清单。待确认的车载电脑不是告警，不进告警栏。
- **改了 IO 点位对应表后的逐仓核对**（ADR 0024）是车辆详情里的一张表：每个仓一行，"开门锁反馈变开、关门变锁着、放东西光幕变有货"三格。工程师在车旁开门、关门、放东西，服务端看到对应读数就自动打勾，对不上的标红。全部打勾，"启用车"才可以按。人不用按"下一步"，所以它不是向导。
- **机台详情**：这台机台的需求和任务，每条写明给了哪台车、排第几，或者为什么还没派；它的区域号的配置（归哪个派车区、开门侧、是否不服务）只读显示，要改去配置页，改配置只有一个入口（产品负责人 2026-10-17）。
- **充电桩详情**：可用还是停用、空着还是占着（被哪台车），以及停用和重新启用的按钮（ADR 0020）。
- **告警栏**：地图页上方固定的一条，界面上的标题写"等你处理的事"（产品负责人 2026-10-17）。
  - 只放告警。每条写明哪台车（或"不属于任何项目"）、出了什么事、等谁处理：是故障的写"等班组长"；不是故障的写"车旁的人处理中"，30 分钟升级后改成"等班组长"；不属于任何项目的写"等管理员处理"（ADR 0013、0014）。等班组长的排在前面，同一类里新的在前。
  - 点一条就打开那台车的车辆详情；不属于任何项目的打开这条故障的说明。
  - 告警一直挂到问题解决，解决了自动消失。不设"已读""知道了"按钮：按了问题也还在，多一个按钮只多一种状态要人理解。
  - 提示（服务端已经自己恢复的事，ADR 0013）不进告警栏，只出现在那台车的最近事件和事件记录里，免得把要人处理的告警淹没。
  - 来了新告警，只靠画面提醒：告警栏变色、计数加一、浏览器标签页标题带上数字（例如"(2) SIMPLE 控制台"），切到别的窗口也看得到。不出声（产品负责人 2026-10-17）。
- **记录与统计页**：上面是统计，下面是事件记录，共用一组筛选条件（车、时间段，事件记录另加任务和账号，ADR 0019）。统计先用表格显示数字。两块各有一个"导出"按钮，把当前筛选结果存成 Excel 能打开的文件（CSV），交客户的运行日志与统计报表时用（产品负责人 2026-10-17）。
- **配置页只用表单**（产品负责人 2026-10-17）：
  - 按类别分块：车辆清单（含 IO 点位对应表）、项目和派车区、固定站点、区域号、任务类型开关、电量线和各种时长。站号旁边显示从地图上读到的站名（ADR 0017）。
  - 改完点"检查改动"，页面列出改前改后的对比和服务端的校验结果，人确认后提交，就是 ADR 0017 的那套步骤。
  - 页面底部是历史版本：谁、什么时候、经哪个入口改的，以及"退回上一版"。
  - 不提供直接编辑整份配置文本的入口。AI 改配置走 MCP（ADR 0016），人改配置只有表单这一种方式。
- **车辆一览页**（ADR 0016）也用同一张地图，只读（产品负责人 2026-10-17）：只画路网、站点和本项目的车，车的颜色和地图页一样；点车只显示在哪、在做什么、现在能不能接任务及原因。机台上不标需求，没有告警栏，没有按钮。地图下方附一张小表，每台车一行写同样的三样东西，方便远远扫一眼。显示的内容仍然只有 ADR 0016 规定的那三样。
- **语言和时间**：全中文。时间一律按服务端的钟显示（ADR 0024），精确到秒，例如 `10:41:07`；不是当天的前面带日期。

## 考虑过的做法

- **以车辆卡片为首页、点进去是车辆页**（初稿）：看不出车在厂里的位置、哪些机台在等货，产品负责人要地图。
- **单独做告警页、任务页、故障处置页**：同一台车的事分散到三处。
- **待确认的车载电脑单独一页，或放进告警栏**：一年碰不到几次，单独一页不值；告警栏只放告警，混进来就多一种东西要人分辨。
- **故障处置做成一步一步的向导**：见上文。
- **新告警响一声**：产品负责人选了只靠画面。另一个缺点是浏览器要求页面打开后有人点过才能出声，电脑重启后不响，表现前后不一。
- **新告警一直响到处理为止**：车间里吵，又没有"知道了"按钮能关。
- **告警设"知道了"按钮**：见上文。
- **配置页另给管理员一个直接编辑整份文本的入口，或者只有文本没有表单**：改大量内容快，但要懂文件格式，敲错一个符号就校验不过，不符合"凭直觉就会"；批量改有 MCP。
- **在机台详情里直接改它的区域号配置**：改配置就有了两个入口。
- **第一版不做导出，要数据时经 MCP 让 AI 取**：交报表是固定要做的事，每次都得找管理员。
- **车辆一览页只用一张表**：看不出车在哪；员工和班组长看到的画面也不一样，要学两套。
- **页面同时适配手机**：现场只有电脑。

## 后果

- 界面的长相（配色、排版、详情以浮窗还是侧栏出现、按钮放在哪）由实现控制台的票定，不在这一篇。产品负责人倾向详情以浮窗形式出现在地图上（2026-10-17）。
- 服务端接口要给出每台车"在做什么、为什么、接下来去哪"、每条需求"给了谁、排第几或为什么没派"的那一句话，以及每个动作能不能按、不能按的原因（ADR 0030）。这些判断只在服务端写一次，控制台、MCP、AI 和测试看到的是同一份。
- `riot-sdk` 要补两样才能画地图：读车的坐标和朝向（现在只读车停在哪个站），以及路径里的弯道控制点（现在读到后丢掉）。地图底图能不能用，要实现时先调一次那个下载接口看看格式。
- 区域号在地图上找不到对应站点的需求（ADR 0002），地图上画不出来，只在需求清单里看得到。
