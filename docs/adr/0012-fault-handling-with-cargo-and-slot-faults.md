# 故障处置在控制台发起、就地做；仓位故障不分种类，坏仓可以停用

车出了故障、车上又有货时，由专业人员在控制台发起故障处置、选动作，车旁的人只按指示做必须亲手做的物理动作，车只报光幕和锁的事实，由服务端判断做完没有。上一代把这些放在车载屏上的异常处置会话里，要带管理员凭据才能开，远程的人什么都做不了；动作名字（续作、补偿清空、强制取出）不看代码猜不出意思。仓位故障的种类很多，但服务端能看到的只有光幕和锁两个数字量和开锁输出，多数坏法和"人还没做"长得一样，所以模型不分种类：只分"服务端直接认出"和"等超时或有人报告"，后面的处置都一样。

本篇补上 ADR 0005 留下的两个缺口：车上有货的任务在控制台没有出口；装货补偿清空归控制台。

## 故障处置

- 故障处置由专业人员（系统管理员或被授权的人，人员与权限另定）在控制台发起，对象是服务端检测到的故障，或专业人员判定的故障。服务端停下交人的车（例如挂起后继续不了、移动单被反复取消或车被反复下线到上限，ADR 0010、0011），以及专业人员要停用的不空闲的车（ADR 0011），专业人员都可以在控制台把它判定为故障，发起故障处置。这样"交人"之后总有出口。
- 车载终端屏上显示服务端给的指示，例如"请取出 3 号仓的货，取完关门"，车旁的人照做。
- 处置有三个动作：
  - **修好后继续**：专业人员确认故障已排除，车带着车上的货接着走这一趟（门锁条件见 ADR 0009）。
  - **取出货物交人工**：对选中的任务，服务端按 ADR 0005 一次开一扇门，车旁的人取出货，服务端看到光幕空、门锁上，这条任务以故障货物交接结束，货由人工送。上一代的"装货补偿清空"就是这个动作，这个说法不再使用。车载终端断联（例如车坏在路上、车载终端没电）时，服务端看不到光幕和锁，由控制台的人确认已取出，和"手动开锁取货"一样。
  - **手动开锁取货**：仓门用信号打不开时，车旁的人拨动锁上的应急位置打开仓门取货，由控制台的人确认已取出；这条任务以故障货物交接结束，这个仓位停用到修好为止。
- 车上有货的任务在控制台没有"放弃"：要么照常送到，要么经故障处置取出货物、以故障货物交接结束。没有车好好的却要放弃车上有货的任务的需求；要停用一台车上有货的车，先把它判定为故障（见上）。
- 故障处置就地做：需要处置时车都已停下（取货站上离站倒计时已停、行驶中被三类急停按住、车体开不动、卸货站本来就不走）。车挡了路，现场人员可以松抱闸把车推开，推开后照样处置；修好就接着走原来的订单（挂起按 ADR 0010）。

## 仓位故障

- 服务端**直接认出**仓位故障，立即停下这台车的全部仓位操作，在控制台告警，等故障处置：
  - 服务端认为本该空的仓（开门装货前、卸货完成后）光幕报有货；
  - 车停着、锁反馈是锁着，光幕却变了；
  - 发了开锁命令，锁反馈没变成开；
  - 车载终端读回的开锁输出撤不掉。
- **认不出**的（门一直开着、关门后光幕一直不符合预期），和"人还没做"分不清：取货站上门开着超过一段时间（厂区配置，默认 6 分钟）在控制台告警，交人判断；卸货站沿用 ADR 0005 的 10 分钟没进展告警。
- 车载屏上有"这个仓有问题"按钮，车旁的人按下，等同服务端直接认出了仓位故障。认不出的那几种主要靠它发现。
- **仓位停用**：故障处置中，专业人员可以停用坏的仓，然后修好后继续；车用其余的仓照常干活，停用的仓不分给任务，直到修好后在控制台重新启用。停用前这个仓得是空的；光幕坏了、读数不可信时，由人确认它是空的。停用的仓不豁免门锁检查：车要行驶，它的锁反馈也必须是锁着（ADR 0009）。所以光幕坏了可以停用这个仓接着跑，锁反馈坏了车就动不了，必须修好，因为服务端分不清"反馈坏了"和"门真开着"。车辆启用前的核对，对停用的仓只核锁、不核光幕（ADR 0011）。
- 软件完全认不出、后果又重的两种，这一版接受风险，靠人看到后报告：锁反馈报锁着、锁实际开着（车在路上门可能被甩开）；卸货时人没取货就关了门、光幕却报空（服务端判送达，货被拉走）。要发现它们得加独立的传感器（例如门位置传感器），这是柜体的硬件决定，另议。

## 开门与维修

- 不设单独的"维护模式"。停用的车（ADR 0011）上，可以在控制台或车载终端上任意开门，可以同时开多扇；这台车在车队调度系统里有执行中的订单时除外（ADR 0011）。重新启用前的核对（仓门全锁、仓位全空）会挡住维修时开过的门和留在仓里的东西。
- 启用的车只按 ADR 0005 一次开一扇；故障处置中，专业人员可以单独打开出故障的那个仓门检修。

## 考虑过的做法

- **沿用上一代，在车载屏上开异常处置会话**：远程的人什么都做不了，现场人员负担重。
- **按零件和坏法细分仓位故障**（光幕卡有货、卡空、跳动，锁反馈卡锁、卡开、两个方向说谎，开锁输出撤不掉，抽屉卡住，门打不开、关不上）：服务端多数分不清，细分只会让模型变复杂，处置却都一样。这份分析只用来确定哪些能直接认出。
- **一个仓坏了整台车就不能用**：三台车少一台就是三分之一的运力，而光幕坏了的仓停用后车仍然安全。
- **停用的仓豁免门锁检查**：坏锁的反馈说不清门开没开，豁免了车可能带着开着的门跑。
- **控制台可以放弃车上有货的任务**：没有这个需求。
- **保留"维护模式"作为一个单独状态**（上一代）：有了车辆启用，停用的车本来就交给人，多一个状态只多一套进出规则。
