# 故障处置在控制台发起、就地做，只有两个动作；仓位故障不分种类，坏仓可以停用

车出了故障时，由专业人员在控制台发起故障处置、选动作，车旁的人只按指示做必须亲手做的物理动作，车只报光幕和锁的事实，由服务端判断做完没有。处置只有两个动作："继续"和"取出货物交人工"，对所有故障都一样；故障分类只是告诉人该找谁修的标签。上一代把这些放在车载屏上的异常处置会话里，要带管理员凭据才能开，远程的人什么都做不了；动作有四个（续作、补偿清空、故障货物交接、强制取出），名字不看代码猜不出意思。产品负责人要求异常处理凭直觉就会、处理方式尽量少且统一，免得以后被不合理的需求越堆越多（2026-10-16）。仓位故障的种类很多，但服务端能看到的只有光幕和锁两个数字量和开锁输出，多数坏法和"人还没做"长得一样，所以模型也不分种类：只分"服务端直接认出"和"等超时或有人报告"，后面的处置都一样。

本篇补上 ADR 0005 留下的两个缺口：车上有货的任务在控制台没有出口；装货补偿清空归控制台。

## 故障处置

- **对象**：服务端检测到的故障，以及专业人员判定的故障。服务端自动恢复不了、停下交人的情况（ADR 0010、0011：同一张单或同一台车 10 分钟内第 3 次需要恢复、被取消后货对不上、挂起后继续不了、在 Matrix 上取消引起的挂起、挂起过又被取消且条件不满足、自己的单变成状态 8、外来单取消不掉或认不准）都算车队调度系统故障。文档没列到的卡住情况，专业人员可以在控制台对任何一台启用的车手动判定故障，要填原因，记进事件记录；只有专业人员能做。
- **故障期间**：一台车上有没结束的故障，就不接新任务，服务端也不再给它发下一张移动单；它身上还没装货的任务挂着"等车恢复"（ADR 0003）。手动判定故障时车如果正在走，不会立刻停下，会走完当前这一移动段、在下一个停靠停下再处置；要保证立刻停住，按车上的急停按钮。人不在车旁时，远程停车用控制台的"急停这台车"（ADR 0018）；它是二类急停，车旁的人能解开，不保证车不走。第一版 SIMPLE 只为仓门未证明锁闭自动下急停（ADR 0009），暂停移动单又被实测证明不可靠，所以不为手动判定另加急停。
- 故障处置由专业人员（系统管理员或被授权的人，人员与权限另定；已定，见 ADR 0014：本篇的"专业人员"指班组长及以上的角色，重新启用仓位归工程师及以上）在控制台发起。车载终端屏上显示服务端给的指示，例如"请取出 3 号仓的货，取完关门"，车旁的人照做。
- **两个动作**，都只在控制台上、只有专业人员能按：
  - **继续**：专业人员确认原因已处理好（零件修好了，或查清了反复取消的人、让他别再点了），服务端核对门锁等条件（ADR 0009）后，让车接着做原来的事：重建移动单、从挂起继续、重新上线，或解除 SIMPLE 的三类急停。车上有货就带着货走完这一趟，没货就回到空闲。刹车计数不因此清零（ADR 0008）。车上有控制台下的急停时，按"继续"不执行，提示"先解除控制台急停"（ADR 0018）。状态 8 的单，人先在车队调度系统里把它结束，服务端读回已结束后再重建。
  - **取出货物交人工**：专业人员选中要取货的任务，服务端按 ADR 0005 一次开一扇门，车旁的人取出货，这条任务以故障货物交接结束，货由人工送。门用信号打不开时，车载屏提示"请拨动锁上的应急位置开门"，车旁的人手动开。服务端看得到光幕空、门锁上就自动算取完；看不到时（车载终端断联、门是手动开的、光幕或锁本身坏了），由控制台的专业人员确认已取出。门是手动开的那个仓要停用到修好为止，但不另设动作：专业人员确认取出时，确认的话改为"货已取出，且已有人亲眼看过门关好、锁舌锁上"，确认后这个仓才停用、车才能继续（产品负责人 2026-10-16）。上一代的"装货补偿清空"和"强制取出"都是这个动作，这两个说法不再使用。
  - 车上还没有这条任务的货的任务，照 ADR 0003 在控制台放弃。
- **结束**：故障处置只以两种方式结束：继续，或停用这台车（ADR 0011，车上没货才能停用，还没装货的任务随停用一起放弃）。取出货物不结束处置：货取完了、原因没查清，车仍不接新任务，免得又被派出去、马上出同样的事。处置中的故障如果按 ADR 0008 自动结束了（例如车载终端重连后读数一致），处置也随之结束。
- **出口一览**：

  | 情况 | 控制台的出口 | 任务的结局（ADR 0003） |
  | --- | --- | --- |
  | 车上还没装这条任务的货（不论车好坏） | 控制台放弃，随时可以 | 控制台放弃 |
  | 车上有货，车正常 | 没有出口，照常送到 | 送达 |
  | 车上有货，车有故障（服务端认出的、自动恢复不了的、人判定的） | 故障处置：继续，或取出货物交人工 | 送达，或故障货物交接 |
  | 车上有货，车载终端断联 | 同上；取出由控制台的人确认 | 故障货物交接 |
  | 要停用一台车 | 车上没货才能停用；有货就等它送完，或它有故障时先经处置取出货物 | 控制台放弃，或故障货物交接 |

- 故障处置就地做：需要处置时车都已停下（取货站上离站倒计时已停、行驶中被三类急停按住、车体开不动、卸货站本来就不走、手动判定后到了下一个停靠）。车挡了路，现场人员可以松抱闸把车推开，推开后照样处置；处理好就接着走原来的订单（挂起按 ADR 0010）。
- **故障分类不决定处置方式**：九类故障和内部、外部之分，只用来在告警上告诉人该找谁修；能不能自动结束看的是服务端能不能看出它好了（ADR 0008）。以后新加一种故障，不为它另设处置动作。

## 仓位故障

- 服务端**直接认出**仓位故障，立即停下这台车的全部仓位操作，在控制台告警，等故障处置：
  - 服务端认为本该空的仓（开门装货前、卸货完成后）光幕报有货；
  - 车停着、锁反馈是锁着，光幕却变了；
  - 发了开锁命令，锁反馈没变成开；
  - 车载终端读回的开锁输出撤不掉。
- 光幕断电、光幕或锁的信号线断了，不去查接线、不另立规则，算进光幕和锁的故障里，按上面能认出就认出，认不出就按下面等人（产品负责人 2026-10-16）。
- **认不出**的（门一直开着、关门后光幕一直不符合预期），和"人还没做"分不清，按"等人没动静"处理：车在取货站或卸货站上，从到站或上一次进展（一扇门关上、一个仓装好或卸完）起超过一段时间（厂区配置，默认 10 分钟）没有新的进展，就在控制台告警，交人判断（接收人见 ADR 0013）。卸货站这条就是 ADR 0005 的 10 分钟没进展告警；取货站上门全关着、一直没人扫码的，照旧由离站倒计时让车离开（ADR 0005）。
- 车载屏上有"这个仓有问题"按钮，车旁的人按下，等同服务端直接认出了仓位故障。认不出的那几种主要靠它发现。车载终端上异常处理用的按钮只有两个：它和解除二类急停（ADR 0009）；停用的车上任意开门是维修用的，不算在内。
- **仓位停用**：故障处置中，专业人员可以停用坏的仓，然后按"继续"；车用其余的仓照常干活，停用的仓不分给任务，直到修好后在控制台重新启用。停用前：
  - 这个仓得是空的；光幕坏了、读数不可信时，由人确认它是空的；
  - 服务端读到它的锁反馈是锁着；
  - 专业人员要确认"已有人在车旁亲眼看过：门关好了，锁舌锁上了"（车旁的人可以拨应急位置把锁锁上），因为这个仓坏过，锁反馈说谎的可能比好仓大（产品负责人 2026-10-16）。手动开过门的仓，这句确认并在"取出货物交人工"的确认取出里一起做。凡是坏仓停用，都要有人亲眼确认过门锁。
  停用的仓不豁免门锁检查：车要行驶，它的锁反馈也必须是锁着（ADR 0009）。车辆启用前的核对，对停用的仓只核锁、不核光幕（ADR 0011）。
- 软件完全认不出、后果又重的两种，这一版接受风险，靠人看到后报告：锁反馈报锁着、锁实际开着（车在路上门可能被甩开）；卸货时货还在仓里、光幕却报空（服务端判送达，货被拉走）。光幕本身只会把没东西误报成有东西，不会反过来（产品负责人 2026-10-16），后一种只会在光幕断电或信号线断了时出现。要发现它们得加独立的传感器（例如门位置传感器），这是柜体的硬件决定，另议。

## 开门与维修

- 不设单独的"维护模式"。停用的车（ADR 0011）上，可以在控制台或车载终端上任意开门，可以同时开多扇；这台车在车队调度系统里有执行中的订单时除外（ADR 0011）。重新启用前的核对（仓门全锁、仓位全空）会挡住维修时开过的门和留在仓里的东西。
- 启用的车只按 ADR 0005 一次开一扇；故障处置中，专业人员可以单独打开出故障的那个仓门检修。

## 考虑过的做法

- **沿用上一代，在车载屏上开异常处置会话**：远程的人什么都做不了，现场人员负担重。
- **按零件和坏法细分仓位故障**（光幕卡有货、卡空、跳动，锁反馈卡锁、卡开、两个方向说谎，开锁输出撤不掉，抽屉卡住，门打不开、关不上，断电、断线）：服务端多数分不清，细分只会让模型变复杂，处置却都一样。这份分析只用来确定哪些能直接认出。
- **按故障类别定不同的处置动作**：每加一类故障就多一套规矩，正是产品负责人担心的"需求越堆越多"。
- **"取出货物交人工"和"手动开锁取货"分成两个动作**：后者只是前者做到一半、门打不开时的退路，分开只让人多学一个名字。
- **"处理好后继续"和挂起的"继续"按钮分成两个入口，车载屏上也能按**：同一件事两个名字、两种计数规矩；产品负责人不希望普通人员接触"继续"。
- **定柜体的接线要求（锁反馈断线读成开、光幕断线读成有货），上线前逐仓拔线实测**：产品负责人不去调查接线，断线算进光幕和锁的故障，后一种风险照旧靠人报告。
- **一个仓坏了整台车就不能用**：三台车少一台就是三分之一的运力，而光幕坏了的仓停用后车仍然安全。
- **停用的仓豁免门锁检查，或停用时不做人工确认**：坏锁的反馈说不清门开没开，豁免或不确认，车可能带着开着的门跑。
- **手动开过门的仓直接自动停用，不做人工确认**：这个仓的门用信号打不开，锁本来就坏了，它的锁反馈最不可信。
- **门开太久和卸货没进展各用一个计时器**（取货站门开 6 分钟、卸货站 10 分钟没进展）：管的是同一件事——车在站上等人、人迟迟没动静。
- **控制台可以放弃车上有货的任务**：没有这个需求。
- **服务端自动恢复不了的情况另立一个"等人处理"状态，和故障并列、共用同一组动作**：名字更贴切（车本身没坏），但多一个概念，规则里处处要写"故障或等人处理"；它们也符合"要专业人员参与才能解决"的故障定义。
- **取出货物就结束处置**：原因没查清的车会马上又被派出去，再出同样的事。
- **手动判定故障时服务端立即下三类急停**：车马上停住，但多了一种急停原因，要和 ADR 0009 的解除规则对上；真要立刻停车，按急停按钮即可。
- **保留"维护模式"作为一个单独状态**（上一代）：有了车辆启用，停用的车本来就交给人，多一个状态只多一套进出规则。
