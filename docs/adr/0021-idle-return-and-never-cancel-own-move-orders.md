# 服务端从不主动取消自己的移动单；空闲的车回自己的等待点，路上不改道

车在走一张移动单时，服务端不为了改主意去取消它：让车走完，到了以后再按新的情况定下一步。取消执行中的订单，车如果正在移动就会猛地停下；车如果因为避障、交通管制本来就停着，才不会猛停（产品负责人的说法，未实测，已记进 #11）。产品负责人不希望 SIMPLE 主动取消自己的移动单（2026-10-16）。这条原则也让空闲返回简单下来：上一代空闲返回有开关、默认关着、不在部署配置里，返回的单子卡住时车一直挂着"空闲返回"，电量跌破线也不进充电队，2026-10-11、10-12 现场都踩过。

## 决定

### 不取消自己的移动单

- 服务端从不主动取消 SIMPLE 自己的移动单，去取货站、卸货站、充电桩、等待点的都一样。路上来了新活、电量跌破线、需求从 MES 消失，都不改道，车到了再说。
- 只有人明确介入时才取消：
  - 在控制台停用车（ADR 0011）；
  - 在控制台放弃一个任务（ADR 0003）：车正开往这个任务的取货站、而这一站没有别的任务了，才取消开往这一站的那张移动单；这一站还有别的任务就照去；
  - 故障处置中的动作（ADR 0012）；
  - 认出手动用车时（ADR 0022），服务端取消这台车上 SIMPLE 所有没结束的移动单。手动用车本身就是人在介入；不取消的话，松着抱闸时排着的单会在抱闸一合上时当场执行，人推完车车就自己开走了（产品负责人 2026-10-16）。
- 外来单不是 SIMPLE 此刻要车执行的单，照 ADR 0011 取消。SIMPLE 自己放弃了的旧单，按 ADR 0011 和 `CONTEXT.md` 也属于外来单、会被取消；它们已经不是 SIMPLE 要的单，所以和"从不取消自己的移动单"不冲突。
- 离开充电桩不需要取消订单：车一开始充电，充电单自己就结束了，SIMPLE 只建下一张单（ADR 0020）。

### 需求从 MES 消失不再结束任务

- 需求一旦受理成任务，MES 里消失不消失都不影响它，它只按自己的结局结束（ADR 0003）。车正开往取货站、任务已分给车但车还没出发、任务挂着"等车恢复"，三种都不撤任务，车照常去；后两种车上并没有开往这一站的移动单，也一样不撤（产品负责人 2026-10-16）。货已经被人拉走的，到站没人扫码，离站倒计时走完车就走，这条任务以站点超时结束、写抑制，不会再派第二次（产品负责人 2026-10-16）。人也可以随时在控制台放弃它。
- 改写 ADR 0003 的"途中从 MES 消失"一节，那一节作废；任务结局里的"途中从 MES 消失"不再出现。需求在受理之前消失，仍照 ADR 0003 不写抑制。
- 宁漏不重仍然成立：站点超时照样写抑制，这条需求不会再派。新接受的代价是车白跑一趟、再等一次离站倒计时；现场的人看到机台上有货就拉走（ADR 0003），所以这种情况多不多，现在不知道。为了量出来，站点超时时事件记录里要记下这条需求当时是否已经不在 MES 里，ADR 0019 的统计就能算出这个频率。换来的是少一条规则，也少一个"消失"的去抖判断。

### 空闲返回

- **一句话**：启用、没有没结束的故障的车，空闲了，又不在自己的等待点上，就去自己的等待点。卸完货没活、充满了（ADR 0020）、让位离桩、刚启用、故障处置按"继续"后车上没货回到空闲，都是这一句，不为每种情况各写一条。已经停在自己等待点上的空闲车待着不动。
- **不设开关**，**不设延时**：车一空闲就走，免得空车堵在卸货站和机台前的通道上。
- **电量优先**：空闲的车电量低于去充电线，就去充电，不去等待点（ADR 0020）；能去的桩都被占着，就先回自己的等待点，在那里等桩。
- **路上不改道**：去等待点的路上来了新活，不打断，车先开到等待点，到了就是空闲的车，按正常派车规则接活，这条活也可能被别的车接走；路上电量跌破去充电线，也是先到等待点再去充电。去等待点的单不会挡住充电：车到了就不再挂着空闲返回。
- 去等待点的单出了意外，和搬运的移动单完全一样按 ADR 0010 和 ADR 0008 的刹车处理。

### 等待点

- 参数配置的车辆清单里，每台车配一个自己的等待点，按"地图 + 站号"写（产品负责人 2026-10-16）。配置校验要求：每台车都要配；两台车不能配同一个；站点在地图上确实存在，不存在就不能提交。之后它从地图上被删了，和固定站点一样（ADR 0015）算配置故障，告警等管理员改；这期间这台车空闲时就停在原地，不做空闲返回。充电桩被从地图上删了也一样算配置故障，这个桩不再分给任何车（ADR 0020）。车只回自己的点，所以 SIMPLE 自己的车之间不会抢点，也不用"等待点不少于车数"这条检查。
- 一个站点只能当充电桩、等待点、固定站点、区域号对应的机台站点（ADR 0002）四者之一。配置里的三种由配置校验在提交时拦住重叠；机台站点是读地图的，地图后来改得和配置重叠了，就算配置故障。等待点设在桩上，空闲的车会一直占着桩；设在机台站点上，空车会堵在机台前。
- 别的产线、别的系统的车停在等待点上，SIMPLE 不看；我们的车照常开过去，被交通管制挡住时 SIMPLE 不自己处理，挡住 10 分钟不动按 ADR 0008 算车队调度系统故障、告警，由人处理（与 ADR 0020 相同）。

## 考虑过的做法

- **路上来了新活，取消去等待点的单直接去取货**：车会猛停；产品负责人不要 SIMPLE 结束一个正在走的订单。
- **车在去等待点的路上跌破去充电线，改去充电**：同上。
- **空闲多久才走（例如 1 分钟）**：多一个计时；空车堵在卸货站前的代价更大。
- **空闲返回设开关**（上一代默认关）：关着时空车留在卸货站，开没开要到现场才知道。
- **每台车一个有顺序的等待点列表，或项目里一池点去最近的空点**（上一代）：会抢点，要排队规则和"点不少于车数"的检查；2026-10-11 现场两台车抢过同一个点。
- **需求半路消失时撤掉任务和停靠**（ADR 0003 原来的做法）：要取消正在开往取货站的移动单。
- **需求半路消失时撤任务、不撤停靠**：车照样开到站，只是少了一条任务，规则反而多一句；不撤任务，最差也只是以站点超时结束。
