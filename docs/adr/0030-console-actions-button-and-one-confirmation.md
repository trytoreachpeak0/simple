# 控制台动作一律按钮加一次确认，只有"急停这台车"一按就停；画面过期时不让按

控制台上的动作清单已经定了（`docs/rules-overview.md` 汇总表一），有轻有重：去充电、停用车、继续、取出货物交人工、改配置、急停这台车。这一篇定它们怎么按。按"方式少而统一"（产品负责人 2026-10-16），同一类动作在哪里按法都一样，人不用记哪个动作要点几下。

厂区 Wi-Fi 会抖，而同一个账号同时开在好几台电脑上（ADR 0029）。要防的是有人对着几秒前的旧画面按了按钮，例如画面上车还没货，按"停用车"的那一秒车上刚装了货。车载屏上同样的问题已经在 ADR 0024 里定过：按钮绑定按下时屏上的那份状态，2 秒没收到新鲜的下发状态按钮变灰，3 秒显示与服务端断开。控制台照同一套来，人在两处看到的表现一样。

## 决定

- **每个动作都是一个按钮，按下后弹出一次确认**，确认框里一句话说清按了会发生什么，例如"停用 agv03：车上 2 条没装货的任务会以控制台放弃结束，SIMPLE 之后不再管这台车"。再按一次确认才执行（产品负责人 2026-10-17）。
- **要填东西的动作，在同一个确认框里填**，不另开页面，也不分几步：手动判定故障填原因（ADR 0012）；停用仓位勾选"已有人亲眼看过门关好、锁舌锁上"（ADR 0012）；取出货物交人工选任务、确认已取出（ADR 0012）；停用车确认列出的、要以控制台放弃结束的任务（ADR 0011）；确认车辆身份核对配对码（ADR 0025、0029）。改参数配置的"改前改后对比、校验、确认"（ADR 0017）也是这一次确认。
- **"急停这台车"是唯一的例外：一按就停，不弹确认框**（产品负责人 2026-10-17）。误按了，用"解除二类急停"让车接着走（ADR 0018）；"解除二类急停"本身照常要确认。
- **按不了的按钮照样显示，变灰，下面写一句为什么**，例如"车上有货，不能停用"、"继续：抱闸松着"。不藏起来，免得人以为没有这个功能。能不能按、为什么不能，由服务端按汇总表一的条件判断后给出，控制台只照着显示。
- **按下确认后**，按钮立刻显示"处理中"，这台车的其他按钮暂时变灰（"急停这台车"除外，见下），直到服务端回话：
  - 做成了，详情直接变成新的样子（状态变了、事件里多出一条），不另弹"成功"；
  - 服务端核对条件不通过，就不执行，用一句话说明原因。
- **服务端核对按下时画面上是什么**：每次按下都带上画面依据的那份状态，服务端发现与这个动作有关的情况已经变了，就不执行，并说明变了什么（例如"车上已经有货"）。"急停这台车"不做这项核对，见下。这和车载终端的常驻按钮带上按下时的下发状态是同一个意思（ADR 0024）。画面来不及变灰时，靠这一条兜底。
- **画面每秒自动更新**，不用手动刷新；一台电脑上按的动作，别的电脑一两秒内看到变化。
- **2 秒没收到新数据，按钮变灰；3 秒没收到，顶上出现红条**，写明"和服务端断开了，数据停在 10:41:07，除急停外的按钮暂时不能按"，地图蒙上一层灰；"停在"的时刻按服务端的钟。这两个时长和车载终端读同一份参数（汇总表二"多久没收到新鲜的下发状态，按钮变灰""……显示与服务端断开"），两处永远是一个值。量法不同：车载终端按消息最多是多久以前写的算（ADR 0024），控制台按浏览器最后一次成功收到服务端回话起算。网络恢复后自动接上，不用刷新页面，也不用重新登录。
- **"急停这台车"不受画面过期和"处理中"的限制**（产品负责人 2026-10-17）：画面过期时、断开红条出现时、这台车有别的动作在"处理中"时，它都不变灰；服务端也不因"画面已经过时"拒绝它。急停是往安全方向走的动作（ADR 0008），对着旧画面按，最坏也只是车停下。只要没收到服务端"已下急停"的确认，不管是请求失败、超时还是回话丢了，按钮上都写明"没收到服务端确认，车可能没停；要保证停住，请按车上的急停按钮"，直到收到确认或画面显示车已在控制台急停中。
- **按下之后正好断线、不知道服务端收没收到**，不自动重发（急停的提示见上一条）。恢复后详情显示车的真实状态，事件里有没有这一条，一看就知道做没做成；没做成的人再按一次。

## 考虑过的做法

- **急停也要确认**：按法完全统一，也不会手一滑把正在跑的车停在通道里；产品负责人要它一按就停。
- **按不了的按钮藏起来**：界面干净，但人会以为没有这个功能，也不知道等什么条件满足才能按。
- **要填东西的动作另开页面或分步填写**：多一种按法。
- **画面过期时急停也变灰**：规矩完全统一，但网络抖的那几秒里急停按不了。
- **只靠画面变灰防旧数据，服务端不核对**：变灰之前的那一两秒仍可能按到旧画面上。
- **断线后自动重发没确认的操作**：网络恢复时情况可能已经变了，重发等于替人在新情况下按了一次。
- **控制台的变灰和断开时长另设参数**：同一件事在两处各配一个值。

## 后果

- 服务端每个动作的接口都要能收"按下时依据的是哪份状态"，并在情况已变时拒绝、给出原因；急停例外。这是控制台和以后的 MCP、AI 共用的同一套接口（ADR 0031）。
- "急停这台车"是控制台上唯一不确认、也不受画面过期限制的按钮，界面上要让它和别的按钮一眼就分得开，具体由实现票定。
